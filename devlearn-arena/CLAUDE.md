# CLAUDE.md — DevLearn Arena

**このファイルは毎回の作業の最初に必ず守る規則である。** REWORK.md の作業指示より優先する。

## 何を作っているか

Linux・Git・Kubernetes・ネットワーク・GitHub を、**動く街の模型**として学ぶ教材。
街の建物と動きは、実際の仕組みを表す。数値は、仕組みが目で見えるよう縮めてあるだけ。
**模型であって飾りではない。** 建物や動きが嘘をつくと、隣の説明文より強く誤解を植え付ける。

読み手は**用語を1つも知らない初心者**。Pod も Kubernetes も知らない前提で書く。

参考にしている作品: PGSimCity（PostgreSQL の内部を 3D の街として見せる教材）。
案内ツアー、コマンドの旅路をカメラが追う、施設をクリックすると中身が見える、壊して直せる、の4つを持つ。

## 層の境界（破らない）

```
src/
  engines/   仕組みの模型（純粋な TypeScript。three.js を import しない）。状態を持ち、変える
  city3d/    three.js の街。状態を読むだけで、変えない
  engine/    描画・カメラ・旅路・ラベル・クリック判定
  ui/        HUD・課題の札・施設の中身・ツアー・用語
```

- `src/engines/**` は three.js を import しない
- `src/city3d/**` は模型の状態を読むだけ。書き換えない
- 地理（施設の位置と経路）は `src/city3d/layout.ts` だけが持つ

## 見た目の規則

- **光は意味を運ぶ。飾りで光らせない。** 光っている所には、必ず何かが起きている
- 色は意味で決める。同じ色を別の意味に使わない（稼働中は緑、待機は黄、失敗は赤、など全体で統一）
- 感嘆符と芝居がかった台詞を使わない。人物に顔を描かない
- 用語を説明なしに出さない。初出で必ず平易な言い換えを添える

## 検証の規則（最重要）

過去の作業で、見た目の要求が何度も守られなかった。原因は**画面を一度も見ずに完了にしたこと**。

1. **見た目に関わる変更は、必ず撮影して PNG を自分で開いて見る。**
   描画の命令が成功したことは、見た目の確認ではない。
   撮影は `node tools/shoot.mjs <名前>` で行う。
2. **ブラウザは同時に1つまで。** WebGL をソフトウェアで描くブラウザは1つで 1〜2 GiB を使う。
   複数同時に立ち上げると、メモリ不足で強制終了される（Exit code 137）。`tools/shoot.mjs` は順番待ちをする。
3. **作ったものが繋がっているかを確かめる。** 新しい部品は import され、呼ばれているか。
   存在するだけで呼ばれていない部品は、完成ではない。`grep` で呼び出し元を確かめる。
4. **テストは振る舞いを確かめる。** 「部品がある」を確かめるテストは無意味。
   操作を与えたら状態がこう変わる、を確かめる。
5. 不具合を直すときは、先にそれを再現する失敗するテストを書く。
6. 変更の前後の画面を撮り、何が変わったかを自分の言葉で書いてからコミットする。

## 作業の流れ

- `npm run typecheck` `npm run lint` `npm run test` を通してからコミットする
- 見た目に関わる項目は、撮影して見てから REWORK.md の [x] を付ける
- 確認を求めず、止まらない
