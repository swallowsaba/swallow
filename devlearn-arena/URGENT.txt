【症状】linux.b.04（探す）で、正しいコマンドを打ったのに達成にならない
- 打った: grep -r timeout /var/log/ | wc -l → 3 が正しく出た
- それでも「結果」の画面が「まだ達成した手順は無い」になる
- 答えの欄に 3 を入れて「答える」を押しても達成にならない（または押せない）

【直すこと】
1. 先に、この症状を再現する失敗するテストを書け（CLAUDE.md 13 章）

2. 判定の形を見直せ。
   今は「端末で調べて答える」の欄に手で答えを入れる形だが、
   **コマンドを打って正しい結果が出た時点で達成**とすること。
   指示書 25 章「実戦ではコマンドを扱う」・docs/content-spec.md 2.4
   「判定は出力の文字列ではなく、模擬環境の状態で行う」に沿う。
   - grep と wc で行数を数える手順 → その組み合わせを実行し、正しい数が出たら達成
   - find でファイルを探す手順 → 実行して、正しい場所が出たら達成
   答えの欄は、コマンドでは答えようがない物（読み取って考える値）にだけ残す。
   この実戦では答えの欄を使わない形にできるなら、そうしろ。

3. 同じ作りの実戦を全て洗い出せ。
   content/lessons の全 131 本で、
   「本物のコマンドを打つ実戦なのに、判定が答えの欄への手入力になっている」物を探し、
   同じようにコマンドの実行で達成する形に直せ。

4. 「答える」のボタンが押せない・押しても何も起きない不具合があれば直せ。

5. docs/content-spec.md 2.4 に、判定の決まりを明記しろ。
   「端末の実戦は、コマンドの実行の結果と模擬環境の状態で判定する。
    答えの欄は、コマンドでは得られない値を答える時だけ使う」

6. 直した後、画面を撮影して自分の目で確かめろ。
   linux.b.04 で grep -r timeout /var/log | wc -l と find / -name app.conf を打ち、
   2 つの手順が達成になり、結果の画面に「できたこと」が並ぶことを見ろ。

7. npm run typecheck と npm run lint と npm run test を通してコミットしろ。
