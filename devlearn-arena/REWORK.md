## 1. 【最優先】可視化を学ぶ対象そのものにする

現状の「村のようす」は、どの任務でも同じ田んぼの絵が出るだけで、学習内容と何の関係もない。
**学ぶ対象の実体をそのまま絵にする。** タブを切り替えるのではなく、任務に応じて中身が決まる。

- [x] 1-1. 任務の `track` に応じて、開いた瞬間に適切な表示を選ぶ。
  `git` → コミットグラフ、`k8s` → クラスタ、`net` → ネットワーク図、`github` → PR、
  `kernel` → ファイルシステム。関係ないタブは押せなくする（薄く表示する）。

- [x] 1-2. **git の可視化を作り直す。**
  - コミットを丸で描き、親から子へ線を引く。**ブランチが分岐したら横にずれて別の列になり、マージで合流する**
  - HEAD とブランチ名を札として描き、`switch` すると**札が移動するアニメーション**を出す
  - 画面の上部に3レーン（作業ツリー / インデックス / HEAD）を常時表示し、
    `git add` でファイルの札が左から真ん中へ、`git commit` で真ん中から右へ**動く**
  - `git rebase` ではコミットが複製されて新しい親にぶら下がる様子を段階的に見せる
  - 変更のあったコミット・ブランチは光らせる

- [x] 1-3. **Kubernetes の可視化を作り直す。**
  - 上段にコントロールプレーン（apiserver / scheduler / controller-manager / etcd）を箱で描く。
    コマンドを打ったとき、**実際に動いた部品を光らせる**（apply→apiserver→etcd→controller→scheduler の順）
  - 下段にノードを並べ、Pod を粒として置く。
    **配置が決まった瞬間、Pod がスケジューラからノードへ飛んで着地する**
  - Deployment → ReplicaSet → Pod の所属を線で結ぶ。ローリングアップデート中は新旧の色を変える
  - Service から、**Endpoints に載っている Pod にだけ線が伸びる**。載っていない Pod には伸びない
  - Pod が消えると煙のように消え、作り直されると降ってくる
  - 各 Pod の状態を色と文字の両方で出す（Pending / Creating / Running / CrashLoopBackOff）

- [x] 1-4. **ネットワークの可視化を作り直す。**
  - 機器を箱、リンクを線で描く。切れているリンクは赤い破線
  - `ping` や `curl` を打つと、**パケットが線の上を1ホップずつ実際に流れる**。
    `deliver` が返す hops をそのまま再生する
  - パケットをクリックすると、その時点のヘッダ全項目（送信元/宛先 IP、MAC、TTL、ポート）を表示する。
    **ホップごとに書き換わった項目を色付きで示す**（TTL が減る、MAC が変わる、IP は変わらない）
  - 届かなかった場合、止まった機器を赤く光らせて理由を出す

- [x] 1-5. **GitHub の可視化を作り直す。**
  - PR のタイムライン（作成 → レビュー → チェック → マージ）を横並びで描く
  - Actions の job を DAG として描き、依存を矢印で結ぶ。
    実行中は回転、成功は緑、失敗は赤、skipped は灰色にし、**失敗の下流に×を伝播させる**

## 2. 【最優先】画面の操作からコマンドを出す

図をクリックしたら、対応するコマンドが**ターミナルに文字として現れて実行される**。
操作とコマンドが結び付き、コマンドを覚えられるのが目的。

- [x] 2-1. 可視化コンポーネントに `onCommand: (line: string) => void` を渡す。
  受け取った側は `TerminalHandle.submit(line)` を呼ぶ。**端末に入力された様子が見えること。**
  即時実行ではなく、1文字ずつ打たれるように見せてもよい。

- [x] 2-2. 最低限これらを操作できるようにする。
  - **クラスタ**: Pod をクリック → `kubectl describe pod <名前>` /
    Pod の×→ `kubectl delete pod <名前>` / ノードの⏸→ `kubectl cordon <名前>` /
    Deployment の ± → `kubectl scale deploy <名前> --replicas=N` /
    「時間を進める」→ `kubectl wait 5`
  - **git**: コミットをクリック → `git show <hash>` /
    ブランチ札 → `git switch <名前>` / 「分岐する」→ `git switch -c <名前>` /
    3レーンのファイル札 → `git add <path>` または `git restore --staged <path>`
  - **ネットワーク**: 機器をクリック → そこから `ping <相手>` /
    リンクをクリック → `ip link set <dev> down`（切る）/ `up`（繋ぐ）。このコマンドを実装する
  - **PR**: チェック → `gh pr checks <番号>` / レビュー欄 → `gh pr review <番号> --approve`

- [x] 2-3. 操作したとき、**なぜそのコマンドになるのかを一行で出す**
  （例:「Pod の中身を見るには describe を使います」）。
