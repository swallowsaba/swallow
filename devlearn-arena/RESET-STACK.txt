利用者の指示により、技術と公開先を一新する。

この段ではコードを書かない。仕様書だけを書き換える。（指示書 2 章）
実装は、この仕様書が固まった後に、別の指示書で行う。

### 引き継ぐ

| 物 | 理由 |

見つかった時だけ、理由を記録に書いてから直す。

【3】技術の決まり
---------------------------------------------------------------------------

- Svelte 5 の runes で書く（$state・$derived・$effect・$props）。
  Svelte 4 までの書き方（export let・$:・ストアの $）を新しいコードで使わない
- TypeScript は strict のまま
- 層の境界を ESLint で強制するのは今まで通り。
  src/engines/**・src/sim/**・src/game/**・src/learning/** は
  Svelte も DOM も Canvas も import しない。
  模型の中で Math.random・Date.now を使わない（決定性）
- 都市の描画は Canvas 2D（決着 D-01）。描画の層は状態を読むだけ
- 依存は必要最小限（指示書 40 章）。入れる物は docs/architecture.md に
  理由を書く
- 検査は Vitest（単体）と Playwright（E2E・撮影）

【4】Cloudflare の構成（無料枠の中）
---------------------------------------------------------------------------

次を調べて決め、docs/architecture.md と docs/deployment.md に書く。

- 静的な配信: Workers の静的アセット、または Pages。どちらにするかを
  選び、理由を書く
- API と MCP: Workers
- 保存: まずブラウザの中（IndexedDB・localStorage）。
  サーバ側が要ると決まった物だけ D1 / KV / R2 を使う。
  何にどれを使うかと、その理由を書く
- AI: Workers AI の無料の割り当ての中（【5】）
- 独自ドメイン: 使うかどうかを決める（無料で使えるか確認する）

### 無料枠の調べ方（指示書 37 章）

実装の時点で公式の情報を確認し、docs/free-services.md に記録する。
古い知識をそのまま信じない。記録する物。

  - 無料で使える量（1 日・1 か月あたり）
  - 制限（1 回あたりの時間・大きさ・同時の数）
  - 課金が始まる条件
  - 無料枠を超えたときに何が起きるか（止まるのか、課金されるのか）

調べる対象: Workers・Workers の静的アセット / Pages・D1・KV・R2・
Durable Objects・Workers AI・独自ドメイン。

### 無料を守る決まり

- 課金が自動で始まる設定にしない。無料の枠を超えたら止まる形を選ぶ
- 超えたときの画面の振る舞いを決める（何ができなくなるか、どう伝えるか）
- 使った量を自分で見られるようにする

### 秘密情報（指示書 41 章）

- リポジトリにも配信物にも置かない
- Cloudflare の Secrets と GitHub Secrets に置く
- VITE_ で始まる環境変数はブラウザに埋め込まれて公開される。
  秘密情報を入れない
- 秘密情報の検査（npm run secrets）を新しい構成でも通す

【5】MCP の 3 つの役目
---------------------------------------------------------------------------

### 5.1 外から使えるリモート MCP サーバ（Workers）

外部の AI クライアント（Claude など）から、このサイトのデータと機能を
道具として呼べるようにする。

決めて書くこと。

- 何を道具として出すか。例: レッスンを探す・レッスンの中身を読む・
  用語を引く・学習の進み具合を読む・都市の状態を読む。
  実際に役に立つ物だけにする（出すこと自体を目的にしない）
- 誰に出すか。誰でも読める物（レッスン・用語）と、本人だけの物
  （進み具合・都市）を分ける。本人だけの物に認証が要るなら、
  無料で実現できる方法を決める
- 書き換える道具を出すかどうか。出す場合、壊される危険を考える
- 使われ方の上限。無料枠に収まるよう、1 日の呼び出しの上限を決める
- 使う仕組み（SDK・転送方式）と、無料枠での動き方を調べて書く

### 5.2 サイトの中の AI 機能

指示書 39 章の絶対の条件: AI がなくても、基本のゲームと学習が
成立すること。AI は足しの機能であって、無いと遊べない物にしない。

決めて書くこと。

- 何に使うか。役に立つ所だけ。例: 実戦でつまずいた時の言い換えの
  ヒント、学習の記録からの次の一手の提案、公聴会の説明の添削。
  無理に使わない
- Workers AI の無料の割り当ての中で収まる形。1 回の呼び出しの
  大きさと、1 日の回数の上限を決める
- 無料枠を超えたときは止める。課金に進まない。
  止まったときの画面の文を決める
- 利用者の入力をそのまま信用しない。入力を命令として扱わない。
  AI の返事をそのまま画面に流さず、形を検査する
- 学習の記録（個人の情報）を外へ出さない形にする

### 5.3 開発の道具としての MCP

Claude Code から自分のサイトを調べる・操作するための物。
公開する物に入れない。置き場所と、公開との分け方を書く。
