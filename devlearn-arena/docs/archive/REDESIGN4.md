# カテゴリごとに独自の街づくり・全体図の作り直し・やり直しの不具合

**上から順に実装し、終えた項目を [x] にする。** 各項目のあと `npm run verify` を通す。最後に `npx playwright test --workers=1` と `npm run build`。
中断しても、このファイルの未完了の項目から再開する。

## 要件（ユーザー指示）

1. 「やり直す」が効かない時がある（進捗が 2/4 などのまま）。
2. 全体図が各カテゴリとつながっておらず、昔の画面のままでゲーム感が薄い。
3. 「やり直す」を押しても街が初期化されない。
4. 地図で道路などを勝手に作れるが、学ぶところと連携していない。
5. 全カテゴリ同じ街づくりをやめ、学習要素の特徴を盛り込んだ独自の街づくりにする。
   - 例 Git：branch で計画、add で仮組み、commit で完成して使える。
   - 例 Kubernetes：worker ノードがビル、Pod が部屋、コンテナの脆弱性を監査する役所など、いろいろ連動する。
6. ゲーム感覚を持ちつつ、各カテゴリの要素とリンクした街づくりにする。

## 調べて分かったこと

- 任務を終えた祝いの画面が全面を覆い、その間は「やり直す」が押せない（押しても何も起きず、進捗が 3/3 のまま）。
- 保存は変更のたびに 400ms 待ってから書くが、街の時間が 350ms ごとに進むと書き込みが永遠に先送りされ、読み込み直すと進捗が古いまま戻る。
- 「やり直す」は任務の進みだけを消し、街（施設・地図）は消さない。

## 設計

### 街 = いま取り組んでいる任務の状態（ターミナルの状態）そのもの
自由に道路や区画を置く道具・予算・需要のシミュレーションはやめる。街はコマンドでしか変わらない。
右の地図は、いまの任務のシェルの状態を、カテゴリごとの見立てで斜め見下ろしの街として描く（打つたびに変わる）。
上の通りには、学んで建設を決めた施設（市民施設）が並び、工事の進み・苦情・評価が出る。

- **Git の街（計画と建設）**
  - ブランチ = 通り（main が本通り、ほかは計画中の通り）。HEAD = 市長の旗
  - コミット = 通り沿いの完成した建物（古い順に並ぶ。マージは 2 本の通りをつなぐ建物、rebase 前の元は薄い影）
  - 作業ツリーの新しいファイル = 計画図（青図）→ `git add` で仮組み（骨組み）→ `git commit` で完成
  - 変更したファイル = 改修工事（足場）、消したファイル = 取り壊し
  - タグ = 記念碑
- **Kubernetes の街（オフィス街と役所）**
  - control-plane = 市役所、worker ノード = オフィスビル（Ready でなければ停電、cordon なら通行止め）
  - Pod = ビルの部屋（Deployment ごとに入居企業の色。Running は明かり、作成中は工事、BackOff/Failed は赤）
  - 置き場の無い Pending の Pod = 待機広場のテント（理由の札）
  - Service = バス停（つながる Pod のビルへ線）、Ingress = 街の門
  - 監査局 = イメージの監査（`:latest` やタグ無しは指摘）
- **シェルの街（ファイルシステムの住宅地）**
  - ディレクトリ = 街区（通り）、ファイル = 家（大きさで階数）、実行できるファイル = 工房、隠しファイル = 塀の中
  - 書き込めない・読めない = 鍵。いまいる場所（cwd）= 市長の旗。プロセス = 働く車
- **ネットワークの街（郵便網）**
  - ホスト = 家・ビル、ルータ = 郵便局、スイッチ = 交差点、リンク = 道路（切れていれば通行止め）
  - IP = 住所の札、ファイアウォール = 検問、DNS = 電話帳局、直前に送ったパケット = 道を走る郵便車
- **GitHub の街（建築確認）**
  - リポジトリ = 市役所、Pull Request = 建築申請の建物（レビュー = 検査員の印、チェック = 検査の結果、マージ = 本通りに完成、閉じた = 取り壊し）
  - Issue = 住民の陳情の掲示板

建物を押すと、それが何か（IT の言葉）・いまの状態・次に進めるコマンド（文章で。ターミナルには打たない）を出す。
「この街のしくみ」の凡例に、見立てと概念とコマンドの対応を並べる。

### 苦情と評価
街の人口や日数ではなく、学びの進みから届く。最初の施設の苦情は就任直後に届き、前の施設の任務を 1 つ終えるたびに次の施設の苦情が届く（街が育つと新しい困りごとが出る）。

### やり直す
「やり直す」は選べるようにする：この要望（任務）を最初から／このカテゴリの街を最初から（施設・任務の進み・要望を聞いた記録を消す）。
祝いの画面に「もう一度」「街に戻る」「次の要望へ」を置き、閉じないと何もできない状態をなくす。
保存は書き込みを先送りし続けないように、最後の書き込みから 1 秒たったら必ず書く。

### 全体図
斜め見下ろしの地方の地図に、5 つの街（シェル・Git・GitHub・Kubernetes・ネットワーク）を実際の施設の建ち具合で描き、道でつなぐ。
街を押すと、右の案内板に建った施設・苦情・次に届く声・進み具合を出し、「この街へ」で作業画面へ。
