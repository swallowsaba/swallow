# ゲームの仕組み

## 1. 役と対応

| ゲーム | 学習 |
|---|---|
| クラブのオーナー兼監督 | 学習者 |
| 選手 | 覚えたコマンド（`grep`、`git commit`、`kubectl get` など） |
| 選手の技 | コマンドのオプション（`-i`、`-r`、`--staged` など） |
| 練習 | レッスン（学びの流れの 5 段） |
| 試合 | 障害対応の任務（既存の任務とボス） |
| 施設 | 学ぶ分野（シェル道場・Git 資料室・k8s 訓練場・通信室・GitHub 会議室） |
| スカウト | 新しいコマンドとの出会い |
| 調子 | 間隔反復（しばらく使わないと下がり、練習すると戻る） |
| 信頼（利用者） | 試合の勝敗で増える。街を育てる |
| 経験値 | 練習と試合で得る。施設の建設と拡張に使う |
| リーグ | 学習の段階（地域リーグ → 2 部 → 1 部 → 国際大会） |
| ホームタウン | 学習の成果が形になった街 |

## 2. 1 週間の進み方

- 1 週間は 7 日。学習者が「次の日へ」を押すと 1 日進む
- 各日に 1 つの予定を入れる: 練習 / スカウト / 休養 / 試合
- 週末（土曜）に試合がある。試合は飛ばせない（勝てなくても進める）
- 日程は学習者が組む。ただし 1 週間に最低 1 回の練習がないと試合に出られる選手が足りなくなる
- 1 シーズンは 10 週。最終週のあとに順位が決まり、昇格・残留が決まる

**時間で追い立てない。** 日付は学習者が押したときだけ進む。現実の時間とは関係ない。

## 3. 選手（コマンド）

### 能力値（0〜100）

| 能力 | 何で上がるか |
|---|---|
| 正確さ | そのコマンドを誤りなく打てた割合 |
| 速さ | 手順の目的を読んでから正しく打つまでの手数の少なさ |
| 応用 | 使ったことのある技（オプション）の種類 |
| 組み合わせ | パイプやリダイレクトで他の選手とつないだ回数 |
| 記憶 | 調子を保てている期間（間隔反復の成績） |

- 総合値は 5 つの平均。札に大きく出す
- 能力値は**実際に打ったコマンドの記録**から計算する。練習の手順を飛ばしたときは上がらない
- 計算は `src/game/players.ts` の純粋な関数。テストで確かめる

### 役割

探索・加工・移動・記録・運用・通信・協働の 7 つ（色は `docs/design/DESIGN.md`）。
試合では相手（障害）に対して、必要な役割の選手が揃っていると作戦ボードに出る。

### 技（オプション）

- 各選手は 2〜6 個の技を持つ（`docs/game/CONTENT.md`）
- 状態は 3 つ: 未習得 / もう少し（練習で 1 回使った）/ 習得済み（練習か試合で 3 回正しく使った）
- 技を覚えると話題の帯に流れる

### 調子（間隔反復）

- 既存の `src/lib/review.ts` の間隔を使う。予定日を過ぎると調子が 1 段下がる
- 段階: 好調 / 普通 / 不調 / 絶不調
- 練習でその選手を使うと戻る
- **調子は試合の勝敗を左右しない。** 試合で使うと「調子が悪い選手です。先に練習しますか」と勧めるだけ
- 事務所の主力選手の行と、話題の帯で知らせる

### スカウト（新しいコマンド）

- 施設のレベルが上がると、スカウトの候補（まだ所属していないコマンド）が現れる
- 候補を迎えるには「入団テスト」（短い練習。学びの流れの 5 段）をこなす
- 迎えた選手は札の一覧に加わる

## 4. 練習（レッスン）

- 練習の画面は、左に端末、右に学びの流れ（5 段）の表示。上の帯と話題の帯は他の画面と共通
- 5 段は `CLAUDE.md` の通り。「体験」は `docs/games/` の遊び
- 練習の最後に、使った選手の能力値の伸びを札の上で数字が回る演出で見せる
- 1 回の練習は 5〜15 分で終わる大きさにする
- 既存の任務のうち、障害対応でないものを練習に作り直す

## 5. 試合（障害対応）

- 既存の障害対応の任務（ボス）を試合にする。相手は障害（「ディスク満杯」「Pod が起動しない」など）
- 画面は `docs/design/mockups/match.html` の通り: 左に端末、中央にピッチ、上に得点板、右に作戦ボードと実況、下に控え
- **ピッチは、その障害の模型の状態を描く。** 例: ディスク満杯なら区域がディレクトリ、相手が大きなファイル、自軍が打ったコマンド
- 学習者が端末でコマンドを打つと、その選手がピッチで動き、結果に応じてパスの線がつながる
- 実況はエンジンの出来事から作る（台本にしない）
- 得点板の残り時間は**模型の時間**。打ったコマンドの数で進む。現実の時間では減らない
- 勝ち: 目標を満たす（例: 空きが 30% 以上）。勝ち点 3
- 引き分け: 目標を満たしたが、危ない手（`rm` で消して空きが戻らない等）を使った。勝ち点 1
- 負け: 模型の時間切れ。勝ち点 0。**負けても罰しない。** 何が足りなかったかを作戦ボードで見せ、再戦できる
- 試合後、使った選手の能力値が伸び、信頼（利用者）が増える

## 6. リーグ

- 相手クラブは 5 つ（架空の名前）。相手の勝ち点は seed から決める
- 地域リーグ: シェルの試合。上位 2 位で 2 部へ
- 2 部: シェル＋Git＋ネットワークの試合
- 1 部: 全分野（Kubernetes と GitHub を含む）
- 国際大会: 複数の分野にまたがる障害（クリア後の遊び）
- 昇格すると、スタジアムが増築され、次の施設の建設が解禁される

## 7. 施設

| 施設 | 分野 | 解禁 |
|---|---|---|
| シェル道場 | シェル | 最初から |
| Git 資料室 | Git | 地域リーグの第 4 週 |
| 通信室 | ネットワーク | 2 部へ昇格 |
| k8s 訓練場 | Kubernetes | 2 部で 5 勝 |
| GitHub 会議室 | GitHub | 1 部へ昇格 |

- レベル 1〜5。経験値で建設・拡張する
- レベルが上がると、その分野の練習とスカウトの候補が増える
- 建設には日数がかかる（2〜4 日）。その間は街に足場とクレーンが立つ

## 8. ホームタウン（街の成長）

街は次の値から**決まる**（`src/game/town.ts` の純粋な関数）:

- 利用者の数 → 建物が建つ範囲の半径と、建物の高さの上限
- リーグ → スタジアムの大きさ（5,000 席 / 18,000 席・照明塔 / 40,000 席・屋根）
- 施設の状態 → 空き地 / 足場とクレーン / 完成（レベルで大きさが変わる）
- 大通り → 利用者 5,000 で開通

同じ値からは必ず同じ街になる。**何かが増えたら、その場所にカメラが寄り、名札が立つ。**
「この 1 年で増えたもの」には、何が増えたかと、その原因（どの練習・どの試合か）を必ず並べて出す。

## 9. 保存

- 既存の保存の仕組み（`src/lib/storage/`）に、クラブの状態を足す
- リロードしても、日付・選手・施設・リーグ・街が全て残る

## 10. 最初の遊び方（チュートリアル）

- 初回は「クラブを作る」から始まる。クラブ名を決め（既定は DevLearn FC）、スタジアムの場所を島の上で選ぶ
- 最初の選手は `ls` と `cd` と `pwd` の 3 人。シェル道場だけがある
- 最初の 1 週間は、日程を組む・練習する・試合に出る・街が育つ、を順に案内する
