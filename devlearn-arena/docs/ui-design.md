# UI デザイン

見た目（字・色・質感）は `docs/visual-design.md`。この文書は**画面の構成・操作・情報の出し方**を決める。

## 1. 原則

- **都市が主役。** 都市画面は全画面の都市ビュー。UI はその上に小さく重ねる
- **UI が都市を覆い尽くさない。** 都市画面で常に出ている UI は、画面面積の 20% 以内
- PC 向け。基準は 1920×1080。最小 1280×720。それ未満は「PC の大きな画面で遊んでください」と案内する
- ダッシュボードにしない。カードを大量に並べない。四角いボタンを大量に並べない
- マウスとキーボード。主要な操作はキーボードでもできる

## 2. 画面の一覧

| 画面 | 役割 | 入り方 |
|---|---|---|
| 都市画面 | 主画面。眺める・作る・選ぶ | 起動直後 |
| 学習ライブラリ | 全分野・全レッスンの一覧と検索、推奨学習順 | 上の帯の「学ぶ」 / L キー |
| 知識グラフ | 分野とレッスンのつながりを見る | 学習ライブラリの切り替え / G キー |
| レッスン画面 | 7 段の学習 | 施設の情報パネル・学習ライブラリ・知識グラフ・ミッション・おすすめの欄 |
| 成長画面 | XP・スキル・学習履歴 | 上の帯の XP を押す |
| ミッション一覧 | 受けられるミッション | 上の帯の「ミッション」 |
| 用語集 | 全用語 | 上の帯の「用語」 / 本文の用語を押す |
| 設定 | 音・動き・文字・画質・ミニマップ・保存 | 上の帯の「設定」 |

## 2.1 ナビゲーション

```text
都市画面（起点）
 ├─ 施設を選ぶ → 情報パネル → 「ここで学ぶ」 → レッスン画面 → 都市画面（変化の場所へ寄る）
 ├─ 学ぶ（L） → 学習ライブラリ ⇄ 知識グラフ（G） → 入口の札 → レッスン画面
 ├─ ミッション → ミッション一覧 → ミッションの実戦 → 都市画面
 ├─ XP → 成長画面 → 修了したレッスン → 入口の札
 ├─ 用語 → 用語集 → 関係するレッスン → 入口の札
 └─ 設定
```

- **どの画面からも 1 回の操作で都市画面に戻れる**（Esc、または上の帯の都市名）
- レッスン画面を途中で抜けると、進んだ段まで保存され、次に開くと続きから始まる
- 戻る操作は 1 つ前の画面へ（ブラウザの「戻る」もハッシュの履歴で同じ動きにする）
- 今どの画面か・どの施設のどのレッスンかを、上の帯に常に表示する
- 画面の切り替えは 0.3 秒以内の動きで、都市が奥に下がる・前に出る（動きを減らす設定では即時）

## 3. 都市画面の構成

```text
┌──────────────────────────────────────────────────────────────┐
│ 上の帯（高さ 48）: 都市名 │ 開発資金 │ XP │ 都市規模 │ 発展段階 │ 学ぶ ミッション 用語 設定 │
├──────────────────────────────────────────────────────────────┤
│ ［おすすめの欄：左上、幅 300、畳める］                         │
│                                                              │
│                     都市ビュー（全画面）                      │
│                                         ［情報パネル：右、幅 360］│
│                                         （建物を選んだ時だけ）   │
│ ［ミニマップ：左下］        ［建設メニュー：下中央］   ［表示切替：右下］│
└──────────────────────────────────────────────────────────────┘
```

| 部品 | 位置と大きさ | 中身 | 出る時 |
|---|---|---|---|
| 上の帯 | 上端、高さ 48 | 都市名・開発資金・XP・都市規模・発展段階・画面への入口（学ぶ・ミッション・用語・設定） | 常に |
| おすすめの欄 | 左上、幅 300、高さ 160 まで（画面の高さが 900 未満では 120 まで）。畳むと見出しだけ | 次に学ぶとよい内容（推奨学習順と学習履歴から）・復習の予定・進行中のミッション | 常に（畳める） |
| 建設メニュー | 下中央、高さ 72 | 道路・区画・施設・公園・取り壊し。選ぶと上に種類の引き出し | 常に（畳める） |
| 情報パネル | 右、幅 360、高さは内容に応じて最大 70% | 建物の名前・レベル・状態・対応分野・ここで学ぶ・ミッション・アップグレード | 建物を選んだ時 |
| ミニマップ | 左下、160×160（画面の高さが 900 未満では 100×100） | 島の形・道路・区画・施設の点と、今の視野の枠。押すとその場所へカメラが動く。都市の回転に合わせて回る | 常に（設定の「ミニマップ」で消せる） |
| 表示切替 | 右下 | 学習の進み・人口・交通・発展段階を色で重ねる | 常に |
| 通知 | 上の帯の下、右寄せ | 1 行の知らせ（学習の成果が都市に反映された、など）。3 秒で消える | 出来事の時 |

常時出ている UI の合計が画面の 20% を超えないこと（`docs/visual-design.md` V9）。
画面の高さが 900 未満でミニマップとおすすめの欄を小さくするのは、1280×720 でもこの 20% に収めるため（`docs/decisions.md` D-18）。

## 4. 操作

| 操作 | マウス | キーボード |
|---|---|---|
| 移動 | 右ドラッグ / 画面端 | W A S D / 矢印 |
| 拡大縮小 | ホイール | + − |
| 回転（90 度） | 中ボタン | Q E |
| 選ぶ | 左クリック | Tab で施設を順に |
| 建設 | 建設メニュー → 左クリック（道路はドラッグ） | B |
| 回転して置く | — | R |
| 取り消し | 右クリック | Esc |
| 学習ライブラリ | 上の帯の「学ぶ」 | L |
| 知識グラフ | — | G |
| 一時停止 | — | Space |
| レッスン・ミッション: 次へ | 左の段の中身の直下の「次へ」 | Enter |
| レッスン・ミッション: 戻る | 「次へ」の左の「戻る」 | Backspace |

- レッスン・ミッションの Enter と Backspace は、端末・入力欄・編集欄に文字を打っている間はその欄が優先（段は動かない）。
  Tab で選んだボタンの上の Enter は、そのボタンを押す。押せない「次へ」は Enter でも進まない

## 5. 情報パネル（建物を選んだ時）

上から:

1. 名前・種類・レベル（Lv と次までの条件）
2. 状態（稼働・建設中・資金不足など）
3. 対応する分野とスキルの値（段階の名前と、何をしたからこの値か）
4. **ここで学ぶ**: おすすめのレッスン 3 つ（推奨順・未修了優先）と「学習ライブラリで全部見る」。**どのレッスンもここから始められる**
5. ミッション（この施設の分野を含むもの。施設の Lv の数まで。`docs/game-design.md` 5 章）
6. アップグレード（費用と効果）

## 6. 学習ライブラリと知識グラフ

- 学習ライブラリ: 分野ごとにテーマとレッスンを並べる。既定の並びは推奨学習順。検索・難易度・修了状況で絞り込み
- レッスンを選ぶと入口の札: 到達目標・目安時間・難易度・推奨前提（未修了なら「先に見ると分かりやすい」）・関連・次に学ぶとよい。
  ボタンは「このまま始める」「先に〇〇を見る」。**禁止のボタンは作らない**
- 知識グラフ: 分野を大きな点、レッスンを小さな点で、推奨前提の辺を矢印で描く。修了した所が光る。押すと入口の札
- 学習ライブラリは都市の上に重ねる大きな窓（画面の 80%）。後ろに都市が見える。閉じると都市に戻る

## 7. レッスン画面

**都市の施設の中で学んでいる体裁**にする（学習サイトに見えすぎない）。

```text
┌──────────────────────────────────────────────────────────────┐
│ 上の帯: 施設名・レッスン名 │ 7 段の進み │ 中断して都市へ           │
├───────────────────────┬──────────────────────────────────────┤
│ 左: 段の中身           │ 右: 図・模擬環境・仮想端末            │
│ （解説・理解・クイズ・  │ （実戦では端末か模擬環境、           │
│  結果・まとめ）         │  解説と理解では図）                   │
│                       │                                      │
│ ─────────────────────│                                      │
│      「戻る」「次へ」 ◀┤                                      │
├───────────────────────┴──────────────────────────────────────┤
│ 下: 推奨前提・関連・次に学ぶとよい                              │
└──────────────────────────────────────────────────────────────┘
```

- 背景は施設の中の景色（施設ごとの自作 SVG）を薄く敷く
- 「次へ」「戻る」は、左の窓の**段の中身の直下**に置く（問題・選択肢を操作した所から、マウスを大きく動かさずに押せる）。
  「次へ」は右端、つまり右の図・端末に接する側に置き、右を操作している時も視線の移動を小さくする。
  中身が短ければボタンは中身のすぐ下に来て、長ければ中身だけが窓の中で巻き、ボタンは窓の下端に留まる
- キーボードでは Enter で次へ、Backspace で戻る（4 章。端末に文字を打っている間は端末が優先）
- ミッションの実戦の画面も、同じ置き方とキーにする
- 7 段の進みは上の帯に横並び。終わった段は戻って見られる
- 左右の境は動かせる。実戦では右（端末）を広くできる
- 用語は本文中で下線、押すと小窓（簡単な説明・なぜ重要か・関連技術）
- 実戦のエラーは、端末の下に「エラー → 内容 → 原因候補 → ヒント」の小窓で出す
- 実戦の右側は、本物の道具がある分野では本物の道具（端末・設定の編集・SQL）、無い概念だけを画面の操作にする（`docs/learning-design.md` 6 章の原則 1〜5）
- 結果とまとめの後、「都市へ戻る」で都市画面へ。変化のあった場所へカメラが寄る

### 7.1 実戦の右側（模擬環境・設定の編集・SQL）

実戦の右側は、形（`docs/content-spec.md` 2.4）ごとに次の画面にする。左の目的・手順・ヒント・結果の出し方は端末と同じ。

画面で操作する模擬環境（模）は、**ドラッグと動きで分かる形**にする（`REWORK-PRACTICE.txt` 原則 3・4）。
操作は「ドラッグして置く」「ドラッグしてつなぐ」「ドラッグして並べ替える」の 3 つだけ。押すだけで済む物（答えを選ぶ・荷物を送る・止まった機器を動かす）はボタンでよいが、ボタンには何をするかを文字で書く。
**文を打つ入力欄は置かない**（「文で操作する」欄・「使える操作」の列・操作の文の記録は無い）。

| 形 | 右側の画面 | 操作 | 操作の結果の動き |
|---|---|---|---|
| つなぐ（`sim-connect`） | 部品・機器を点（自作 SVG の記号と名前）、つながりを線で描く。何を確かめるかを書いた「送る」のボタンを上に並べる | 点から点へドラッグして線を引く（引いている間、指先まで線が伸び、つなぐ先の上で「〜へつなぐ」と出る）。線を押すと外れる。止まった機器の「動かす」を押す | つながると、線を光の粒が流れる。つながらない組み合わせは、ドラッグの途中で線と点が赤くなって理由が出て、放しても線は引けない。送ると荷物が線をたどって進み、届けば宛先が緑に光る。届かなければ、止まった機器が赤くなり「ここで止まった」と理由が出る |
| 並べる（`sim-order`） | 段を縦に並べ、段の中に札を横に並べる。左に流れの線。かかる時間と合計を添える。並べていない札は下の置き場 | 札をドラッグして、並んだ札の上（その位置に入る）・一番下・段の間（並行の時は新しい段）・置き場（外れる）へ落とす | 並べるたびに、上の段から順に光って処理が進む。順が違うと、止まった段が赤くなり理由（「〜には、先に〜が要る」）が出て、その先の段は暗いまま。最後まで流れると「最後まで流れた」と合計の時間が出る |
| 置く（`sim-assign`） | 枠を並べ、枠の中に札を入れる。枠の容量と使った量を数と棒で示す。入れていない札は下の置き場 | 札を枠へドラッグして入れる（運んでいる間、上にある枠が光る）。枠から別の枠へドラッグすると移り、置き場へドラッグすると戻る | 入れた瞬間に枠が光り、数と棒が動く。入らない物は枠が赤く光って揺れ、理由が 1 行出る。全て入れたのに合っていなければ、置き違えた札が赤くなる |
| 読み取って答える（`sim-read`） | 表・グラフ・ログ・項目と値を並べ、その横に問いと答えのボタン | 読む所（表の行・ログの行・項目・グラフ）を押すと、その部分が強調され、大きく写した物（拡大）が問いの上に出る。もう一度押すと戻る。答えを押して選ぶ | 拡大は小さく開く動きで出る。グラフの拡大には点ごとの値を添える |
| 設定の編集（`editor`） | 設定ファイルの編集欄（等幅）と、確かめた結果 | 本物の書式で書いて「保存して確かめる」 | 保存の後に打った本物のコマンドの出力を、確かめた結果に出す |
| ブラウザ内 SQL（`sql`） | SQL の入力欄と、結果の表 | 書いて「実行」 | 結果の表を出す |

- 動きを減らす設定（ゲームの設定と OS の設定）では、動きを即時にする（終わりの形をすぐ出す。光の粒は出さない）
- キーボードでは、札・点で Enter（か Space）を押して持ち上げ、置く先の枠・段・点で Enter を押すと置く（Esc でやめる）。マウスで押しただけでは持ち上げない（マウスの操作はドラッグだけ）
- 画面には物の名前だけを出す（式に書く ID は出さない）。左の目的・手順に出てくる物の名前と、画面の名前は同じにする（原則 5）
- 操作の誤りは、その場の赤い印と 1 行の理由に加えて、端末と同じ「エラー → 内容 → 原因候補 → ヒント」の小窓で出す
- 「初めに戻す」で初期状態に戻せる（ヒントの記録は残る。その場の赤い印も消える）
- 結果の段には、画面でした操作を画面の名前で言い表して並べる（「「キーボード」から「CPU」へ線を引いた」）

## 8. 名札と情報表示

- 名札は互いに重ならず、建物を隠さない。重なりそうなら位置をずらし、引き出し線で結ぶ。遠い名札は小さくせずに間引く
- 表示切替: 学習の進み（施設ごとの習熟を色で）・人口・交通・発展段階
- 数字には必ず単位か意味を添える

## 9. 状態と空の画面

- 読み込み中: 都市の輪郭が描かれていく演出（2 秒以内）
- 初回: 都市の作り方と学び方を、画面の該当箇所を示しながら 3 回に分けて説明する（いつでも飛ばせる）
- エラー: 何が起きたか・どうすればよいかを 1 行ずつ。データを失わない
