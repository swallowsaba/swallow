# UI デザイン

見た目（字・色・質感）は `docs/visual-design.md`。この文書は**画面の構成・操作・情報の出し方**を決める。

## 1. 原則

- **都市が主役。** 都市画面は全画面の都市ビュー。UI はその上に小さく重ねる
- **UI が都市を覆い尽くさない。** 都市画面で常に出ている UI は、画面面積の 20% 以内
- PC 向け。基準は 1920×1080。最小 1280×720。それ未満は「PC の大きな画面で遊んでください」と案内する
- ダッシュボードにしない。カードを大量に並べない。四角いボタンを大量に並べない
- マウスとキーボード。主要な操作はキーボードでもできる
- 市政（`docs/decisions.md` D-20）の画面は、今の画面構成を土台に足す。全面的な作り替えはしない。色・字・余白は今の決まりのまま。レッスン画面は D-07 のまま（施設の中に入る別の画面）

## 2. 画面の一覧

| 画面 | 役割 | 入り方 |
|---|---|---|
| 都市画面 | 主画面。眺める・作る・選ぶ | 起動直後 |
| 学習ライブラリ | 全分野・全レッスンの一覧と検索、推奨学習順 | 上の帯の「学ぶ」 / L キー |
| 知識グラフ | 分野とレッスンのつながりを見る | 学習ライブラリの切り替え / G キー |
| レッスン画面 | 7 段の学習 | 施設の情報パネル・学習ライブラリ・知識グラフ・ミッション・おすすめの欄 |
| 成長画面 | XP・スキル・学習履歴 | 上の帯の XP を押す |
| ミッション一覧 | 受けられるミッション | 上の帯の「ミッション」 |
| 用語集 | 全用語 | 上の帯の「用語」 / 本文の用語を押す |
| 設定 | 音・動き・文字・画質・ミニマップ・保存 | 上の帯の「設定」 |
| 市政の窓（10 章） | 許認可の一覧・申請の詳細・公聴会・議会の採決・異議申し立ての知らせ・選挙・任期の終わり・受信箱・予算・市内新聞・褒賞の一覧・始め方の選択 | 上の帯の「市政」とその引き出し・上の帯の数字・都市の上の看板・知らせ・キー（4 章） |
| 表示切替の窓（11 章） | ヒートマップ・グラフ・平易な言葉の説明 | 右下の表示切替 / V キー / 上の帯の支持率 |

- 市政の窓と表示切替の窓は、都市画面の上に重ねる窓で、別の画面にしない（都市が後ろに見え、閉じると都市画面のまま）

## 2.1 ナビゲーション

```text
都市画面（起点）
 ├─ 施設を選ぶ → 情報パネル → 「ここで学ぶ」 → レッスン画面 → 都市画面（変化の場所へ寄る）
 ├─ 学ぶ（L） → 学習ライブラリ ⇄ 知識グラフ（G） → 入口の札 → レッスン画面
 ├─ ミッション → ミッション一覧 → ミッションの実戦 → 都市画面
 ├─ XP → 成長画面 → 修了したレッスン → 入口の札
 ├─ 用語 → 用語集 → 関係するレッスン → 入口の札
 ├─ 市政 → 許認可の一覧 → 申請の詳細 → 公聴会 → 「この論点を学ぶ」→ 入口の札 → レッスン画面 → 公聴会へ戻る
 │        受信箱・予算・市内新聞・褒賞の一覧（記事・請願を押すと、その場所へカメラが寄る）
 ├─ 都市の上の看板（申請中の敷地）→ 申請の詳細
 ├─ 表示切替（V）→ ヒートマップ・グラフ・説明 → 原因の場所へカメラが寄る
 └─ 設定
```

- **どの画面からも 1 回の操作で都市画面に戻れる**（Esc、または上の帯の都市名）
- レッスン画面を途中で抜けると、進んだ段まで保存され、次に開くと続きから始まる
- 戻る操作は 1 つ前の画面へ（ブラウザの「戻る」もハッシュの履歴で同じ動きにする）
- 今どの画面か・どの施設のどのレッスンかを、上の帯に常に表示する
- 画面の切り替えは 0.3 秒以内の動きで、都市が奥に下がる・前に出る（動きを減らす設定では即時）
- 公聴会の窓から入ったレッスンを終える・中断すると、都市画面に戻り、同じ公聴会の窓が開いた状態に戻る（公聴会は待っている。`docs/game-design.md` 20 章）

## 3. 都市画面の構成

```text
┌──────────────────────────────────────────────────────────────┐
│ 上の帯（高さ 48）: 都市名 │ 日付と速さ │ 開発資金 財政 │ 支持率 政治資本 任期 │ XP │ 規模・段階 │ 市政 学ぶ ミッション 用語 設定 │
├──────────────────────────────────────────────────────────────┤
│ ［おすすめの欄：左上、幅 300、畳める］                         │
│                                                              │
│                     都市ビュー（全画面）                      │
│                                         ［情報パネル：右、幅 360］│
│                                         （建物を選んだ時だけ）   │
│ ［ミニマップ：左下］        ［建設メニュー：下中央］   ［表示切替：右下］│
└──────────────────────────────────────────────────────────────┘
```

| 部品 | 位置と大きさ | 中身 | 出る時 |
|---|---|---|---|
| 上の帯 | 上端、高さ 48 | 都市名・日付と速さ（止める・1 倍・2 倍・3 倍）・開発資金・財政・支持率・政治資本・任期の残り・XP・都市規模と発展段階・画面への入口（市政・学ぶ・ミッション・用語・設定）。中身は 3.1 | 常に |
| おすすめの欄 | 左上、幅 300、高さ 160 まで（画面の高さが 900 未満では 120 まで）。畳むと見出しだけ | 次に学ぶとよい内容（推奨学習順と学習履歴から）・復習の予定・進行中のミッション | 常に（畳める） |
| 建設メニュー | 下中央、高さ 72 | 道路・区画・施設・公園・取り壊し。選ぶと上に種類の引き出し | 常に（畳める） |
| 情報パネル | 右、幅 360、高さは内容に応じて最大 70% | 建物の名前・レベル・状態・対応分野・ここで学ぶ・ミッション・アップグレード | 建物を選んだ時 |
| ミニマップ | 左下、160×160（画面の高さが 900 未満では 100×100） | 島の形・道路・区画・施設の点と、今の視野の枠。押すとその場所へカメラが動く。都市の回転に合わせて回る | 常に（設定の「ミニマップ」で消せる） |
| 表示切替 | 右下 | 押すと表示切替の窓（11 章）。今重ねている表示の名前と凡例の小さな帯 | 常に |
| 通知 | 上の帯の下、右寄せ | 1 行の知らせ（学習の成果が都市に反映された・申請の段階が進んだ・請願が届いた・公聴会の日が来た、など）。3 秒で消える。市政の知らせは押すとその窓が開く | 出来事の時 |
| 申請の看板 | 都市の上（申請中の敷地。`docs/city-design.md` 9.1） | 施設の名前・段階・反対率・残りの日数。名札と同じ扱い（8 章）で、UI の面積に数えない | 申請がある時 |
| 市政の窓・表示切替の窓 | 10・11 章 | — | 開いた時だけ |

常時出ている UI の合計が画面の 20% を超えないこと（`docs/visual-design.md` V9）。
画面の高さが 900 未満でミニマップとおすすめの欄を小さくするのは、1280×720 でもこの 20% に収めるため（`docs/decisions.md` D-18）。

**常時出す物と、開いて見る物を分ける**（`docs/decisions.md` D-20 で足す物が多いため）。

- 1280×720 の常時の UI は、足す前で 19.6%（`docs/progress/phase-12.md`）。余りは 0.4% しか無い。**足す物は全て上の帯（高さ 48 のまま）の中に収め、常時の部品の数と大きさを増やさない**
- 常時: 上の帯の数字（日付と速さ・財政・支持率・政治資本・任期の残り）と、上の帯の「市政」の入口と、その上の数の印（公聴会を待つ申請・届いた請願の数）だけ
- 開いて見る: 許認可の一覧・申請の詳細・公聴会・議会の採決・選挙・任期の終わり・受信箱・予算・市内新聞・褒賞の一覧・表示切替の窓・需要（区画を塗る道具を選んだ時の引き出しの中）
- 都市の上に出す物（申請の看板・反対する人の影・止まった記号）は名札と同じく都市の一部として描き、UI の面積に数えない

### 3.1 上の帯の中身

| 項目 | 中身 | 押すと |
|---|---|---|
| 都市名 | 都市の名前 | 都市画面に戻る（2.1） |
| 日付と速さ | 「2 年目 14 週」と、止める・1 倍・2 倍・3 倍の 4 つの小さなボタン（今の速さが金） | 速さが変わる |
| 開発資金・財政 | 数字。財政が赤字の間は `state.bad` の色と「赤字」 | 予算の窓（10.9） |
| 支持率 | 数字と、4 週前からの増減の矢印 | 表示切替の窓の説明（11.3） |
| 政治資本 | 数字 | 予算の窓の政治資本のつまみ（10.9） |
| 任期の残り | 「選挙まで 38 週」 | 選挙の見込み（今の支持と投票率の見込み・果たした公約。10.6 と同じ表） |
| XP・都市規模と発展段階 | 今のまま | 成長画面 |
| 市政 | 入口。上に数の印（公聴会を待つ申請＋届いた請願） | 市政の引き出し（許認可・受信箱・予算・新聞・褒賞）。それぞれ数の印を持つ |

- 1600 未満の幅では、数字の見出しを記号（自作 SVG のアイコン）にし、名前は指した時の小窓で出す。数字は削らない
- 数字には単位か意味を添える（8 章）: 「支持 54%」「政治資本 10」

## 5. 情報パネル（建物を選んだ時）

上から:

1. 名前・種類・レベル（Lv と次までの条件）
2. 状態（申請の段階と残りの日数・工事中・稼働・停電・資金不足など）。申請中は「申請の詳細を見る」（10.2）
3. 対応する分野とスキルの値（段階の名前と、何をしたからこの値か）
4. **ここで学ぶ**: おすすめのレッスン 3 つ（推奨順・未修了優先）と「学習ライブラリで全部見る」。**どのレッスンもここから始められる**
5. ミッション（この施設の分野を含むもの。施設の Lv の数まで。`docs/game-design.md` 5 章）
6. アップグレード（費用と効果。押すと申請になる。見込みの反対の理由の上位 2 つを添える）
7. 都市への効き（雇用・電力の使用量・騒音。`docs/game-design.md` 13・24 章）

- 公共サービス・発電所・褒賞の建物の情報パネルは、1・2・7 と、行き届く範囲（押すとその範囲を色で示す）だけを出す。「ここで学ぶ」は無い（`docs/city-design.md` 9.3）
- **申請中・工事中・停電中の施設でも、4「ここで学ぶ」は押せる**（`docs/game-design.md` 20 章）

## 6. 学習ライブラリと知識グラフ

- 学習ライブラリ: 分野ごとにテーマとレッスンを並べる。既定の並びは推奨学習順。検索・難易度・修了状況で絞り込み
- レッスンを選ぶと入口の札: 到達目標・目安時間・難易度・推奨前提（未修了なら「先に見ると分かりやすい」）・関連・次に学ぶとよい。
  ボタンは「このまま始める」「先に〇〇を見る」。**禁止のボタンは作らない**
- 知識グラフ: 分野を大きな点、レッスンを小さな点で、推奨前提の辺を矢印で描く。修了した所が光る。押すと入口の札
- 学習ライブラリは都市の上に重ねる大きな窓（画面の 80%）。後ろに都市が見える。閉じると都市に戻る

## 7. レッスン画面

**都市の施設の中で学んでいる体裁**にする（学習サイトに見えすぎない）。

```text
┌──────────────────────────────────────────────────────────────┐
│ 上の帯: 施設名・レッスン名 │ 7 段の進み │ 中断して都市へ           │
├───────────────────────┬──────────────────────────────────────┤
│ 左: 段の中身           │ 右: 図・模擬環境・仮想端末            │
│ （解説・理解・クイズ・  │ （実戦では端末か模擬環境、           │
│  結果・まとめ）         │  解説と理解では図）                   │
│                       │                                      │
│ ─────────────────────│                                      │
│      「戻る」「次へ」 ◀┤                                      │
├───────────────────────┴──────────────────────────────────────┤
│ 下: 推奨前提・関連・次に学ぶとよい                              │
└──────────────────────────────────────────────────────────────┘
```

- 背景は施設の中の景色（施設ごとの自作 SVG）を薄く敷く
- 「次へ」「戻る」は、左の窓の**段の中身の直下**に置く（問題・選択肢を操作した所から、マウスを大きく動かさずに押せる）。
  「次へ」は右端、つまり右の図・端末に接する側に置き、右を操作している時も視線の移動を小さくする。
  中身が短ければボタンは中身のすぐ下に来て、長ければ中身だけが窓の中で巻き、ボタンは窓の下端に留まる
- キーボードでは Enter で次へ、Backspace で戻る（4 章。端末に文字を打っている間は端末が優先）
- ミッションの実戦の画面も、同じ置き方とキーにする
- 7 段の進みは上の帯に横並び。終わった段は戻って見られる
- 左右の境は動かせる。実戦では右（端末）を広くできる
- 用語は本文中で下線、押すと小窓（簡単な説明・なぜ重要か・関連技術）
- 実戦のエラーは、端末の下に「エラー → 内容 → 原因候補 → ヒント」の小窓で出す
- 実戦の右側は、本物の道具がある分野では本物の道具（端末・設定の編集・SQL）、無い概念だけを画面の操作にする（`docs/learning-design.md` 6 章の原則 1〜5）
- 結果とまとめの後、「都市へ戻る」で都市画面へ。変化のあった場所へカメラが寄る

### 7.1 実戦の右側（模擬環境・設定の編集・SQL）

実戦の右側は、形（`docs/content-spec.md` 2.4）ごとに次の画面にする。左の目的・手順・ヒント・結果の出し方は端末と同じ。

画面で操作する模擬環境（模）は、**ドラッグと動きで分かる形**にする（`REWORK-PRACTICE.txt` 原則 3・4）。
操作は「ドラッグして置く」「ドラッグしてつなぐ」「ドラッグして並べ替える」の 3 つだけ。押すだけで済む物（答えを選ぶ・荷物を送る・止まった機器を動かす）はボタンでよいが、ボタンには何をするかを文字で書く。
**文を打つ入力欄は置かない**（「文で操作する」欄・「使える操作」の列・操作の文の記録は無い）。

| 形 | 右側の画面 | 操作 | 操作の結果の動き |
|---|---|---|---|
| つなぐ（`sim-connect`） | 部品・機器を点（自作 SVG の記号と名前）、つながりを線で描く。何を確かめるかを書いた「送る」のボタンを上に並べる | 点から点へドラッグして線を引く（引いている間、指先まで線が伸び、つなぐ先の上で「〜へつなぐ」と出る）。線を押すと外れる。止まった機器の「動かす」を押す | つながると、線を光の粒が流れる。つながらない組み合わせは、ドラッグの途中で線と点が赤くなって理由が出て、放しても線は引けない。放した点は赤く光って揺れ、その下に「つなげない: 理由」が 1 行出る（次に操作するまで残る）。送ると荷物が線をたどって進み、届けば宛先が緑に光る。届かなければ、止まった機器が赤くなり「ここで止まった」と理由が出る |
| 並べる（`sim-order`） | 段を縦に並べ、段の中に札を横に並べる。左に流れの線。かかる時間と合計を添える。並べていない札は下の置き場 | 札をドラッグして、並んだ札の上（その位置に入る）・一番下・段の間（並行の時は新しい段）・置き場（外れる）へ落とす | 並べるたびに、上の段から順に光って処理が進む。順が違うと、止まった段が赤くなり理由（「〜には、先に〜が要る」）が出て、その先の段は暗いまま。最後まで流れると「最後まで流れた」と合計の時間が出る |
| 置く（`sim-assign`） | 枠を並べ、枠の中に札を入れる。枠の容量と使った量を数と棒で示す。入れていない札は下の置き場 | 札を枠へドラッグして入れる（運んでいる間、上にある枠が光る）。枠から別の枠へドラッグすると移り、置き場へドラッグすると戻る | 入れた瞬間に枠が光り、数と棒が動く。入らない物は枠が赤く光って揺れ、理由が 1 行出る。全て入れたのに合っていなければ、置き違えた札が赤くなって揺れ、「置き違えた札: 「札」（今は「枠」）」が 1 行出る（正しい枠は言わない。初めから置き違えのある並びでは、札を動かすまで行は出さず、赤い縁だけ） |
| 読み取って答える（`sim-read`） | 表・グラフ・ログ・項目と値を並べ、その横に問いと答えのボタン | 読む所（表の行・ログの行・項目・グラフ）を押すと、その部分が強調され、大きく写した物（拡大）が問いの上に出る。もう一度押すと戻る。答えを押して選ぶ | 拡大は小さく開く動きで出る。グラフの拡大には点ごとの値を添える |
| 設定の編集（`editor`） | 設定ファイルの編集欄（等幅）と、確かめた結果 | 本物の書式で書いて「保存して確かめる」 | 保存の後に打った本物のコマンドの出力を、確かめた結果に出す |
| ブラウザ内 SQL（`sql`） | SQL の入力欄と、結果の表 | 書いて「実行」 | 結果の表を出す |

- 動きを減らす設定（ゲームの設定と OS の設定）では、動きを即時にする（終わりの形をすぐ出す。光の粒は出さない）。疑似要素の動き（並べるの流れの線など）も止める
- キーボードでは、札・点で Enter（か Space）を押して持ち上げ、置く先の枠・段・点で Enter を押すと置く（Esc でやめる）。マウスで押しただけでは持ち上げない（マウスの操作はドラッグだけ）
- 画面には物の名前だけを出す（式に書く ID は出さない）。左の目的・手順に出てくる物の名前と、画面の名前は同じにする（原則 5）
- 操作の誤りは、その場の赤い印と 1 行の理由に加えて、端末と同じ「エラー → 内容 → 原因候補 → ヒント」の小窓で出す
- 「初めに戻す」で初期状態に戻せる（ヒントの記録は残る。その場の赤い印も消える）
- 結果の段には、画面でした操作を画面の名前で言い表して並べる（「「キーボード」から「CPU」へ線を引いた」）

## 8. 名札と情報表示

- 名札は互いに重ならず、建物を隠さない。重なりそうなら位置をずらし、引き出し線で結ぶ。遠い名札は小さくせずに間引く
- 表示切替: 11 章
- 数字には必ず単位か意味を添える

## 9. 状態と空の画面

- 読み込み中: 都市の輪郭が描かれていく演出（2 秒以内）
- 初回: 都市の作り方と学び方を、画面の該当箇所を示しながら 3 回に分けて説明する（いつでも飛ばせる）
- エラー: 何が起きたか・どうすればよいかを 1 行ずつ。データを失わない

## 10. 市政の窓

`docs/game-design.md` 15〜25・27 章の仕組みの画面。見た目は今の HUD の窓のまま（`docs/visual-design.md` 4 章）。カードを並べない。数字には意味を添える。

### 10.0 窓の重ね方

- **窓は重ねて開ける。都市を全部覆わない**
  - 小さな窓（幅 400、高さは内容に応じて最大 60%）: 許認可の一覧・申請の詳細・受信箱・予算・市内新聞・褒賞の一覧・異議申し立ての知らせ・表示切替の窓。右端から左へ、ずらして重ねる。見出しを掴んで動かせ、畳むと見出しだけになる
  - 大きな窓（幅 720、高さ最大 70%、中央）: 公聴会・議会の採決・選挙・任期の終わり・始め方の選択。開いている間、都市の時間は止まる（`docs/game-design.md` 13.1）
  - 同時に開けるのは小さな窓 3 つと大きな窓 1 つまで。4 つ目の小さな窓を開くと、一番前に触った窓が畳まれる
  - 開いた窓の合計は画面の 60% を超えない（超える時は、古い窓から畳む）。都市が後ろに必ず見える
- 情報パネル（5 章）と小さな窓は重ならないように並ぶ（情報パネルがある時は、窓はその左に出る）
- Esc で一番上の窓から閉じる。どの窓からも 1 回の操作で都市画面に戻れる（2.1）

### 10.1 許認可の一覧

- 申請を 1 行ずつ: 名前・場所（地区の名前）・段階（8 段の小さな進みの印。今の段が金）・反対率（数と短い棒）・残りの日数・待っている事（「公聴会を開ける」「議会の日まで 3 日」）
- 並びは、市長の手が要る物（公聴会・申し立て）を先、次に残りの日数の短い順
- 行を押すと申請の詳細（10.2）。行の場所の印を押すと、その敷地へカメラが寄る
- 終わった申請（完成・否決・取り下げ）は、下の「終わった申請」に 1 任期分を畳んで残す

### 10.2 申請 1 件の詳細

上から:

1. 名前・場所・段階の進み（8 段。日付付き）・残りの日数・費用（取り分けた額と財布）
2. 反対率（大きな数字）と、理由ごとの内訳（理由の名前・割合の棒・反対する集団・多い層）。合計が反対率と一致する
3. 理由を押すと、その理由の強さの元になった模擬の値（「半径 4 の住まいで、夜の騒音が 12 増える見込み」）と、その場所のヒートマップ
4. 先回りの譲歩（反対の受付の間だけ。`docs/game-design.md` 17.1）
5. この申請が通った時の得（雇用・技術力・税収・戸数。議員が見る値）
6. 取り下げ（確かめてから）

- 公聴会の段に入ると「公聴会を開く」が金のボタンになる

### 10.3 公聴会の窓

- 左: 論点の列（反対率の内訳で 5% 以上の理由）。論点ごとに、理由の名前・割合・反対する集団・出した手と結果
- 右: 選んだ論点の、出せる手の 3 種類を横に並べる
  - **譲歩する**: 候補ごとに、効き（どの値がどれだけ下がるか）と損（資金・施設の効き）を並べて選ぶ。技術の代案は分野と段階の印を付ける
  - **説明する**: 今のスキル段階で出せる候補の文を並べる（質は出さない）。出せない段階の候補は、文を伏せて「〇〇（分野）初級で出せる説明が 1 つある」と示す。下に「この論点を学ぶ」（関係するレッスン。押すと入口の札。`docs/game-design.md` 20 章）
  - **押し切る**: 使う政治資本と、信頼が下がる集団
- 手を出すと、反対率と内訳の棒がその場で動き、住民と議員がどう受け取ったかを 1 行で出す（`why`）
- 下: 「公聴会を終える」（手を出していない論点が残っていれば、その数を添える）
- スキルが無い時も、譲歩と押し切るは必ず出る（説明の列が空なら「今出せる説明は無い。学ぶと増える」と示す）

### 10.4 議会の採決の画面

- 7 人を横に並べる（自作 SVG の人の影と名前・主な論点の記号）。1 人ずつ、0.4 秒ごとに賛否が出る（動きを減らす設定では一度に）
- 各人の下に、なぜそう判断したかを 1 行（`docs/game-design.md` 18.2）
- 上に賛成の数と「可決（4 以上）」「否決」
- 議会の日の前に開いた時は「議員を説得する」（政治資本 3。1 人を選ぶ）を出す。各人の今の見込み（賛成・反対の向きと、効いている項）も見られる
- 同意の案件（`docs/game-design.md` 15.2）は採決の画面を出さず、知らせと新聞だけ

### 10.5 異議申し立ての知らせ

- 知らせ（3 章）と、許認可の一覧の行の赤い印。押すと小さな窓: 申し立てた集団・理由・止まる日数・取り下げさせる 2 つの方法（追加の譲歩・政治資本 4）と、それぞれの損

### 10.6 選挙の画面

- 選挙の日に開く（大きな窓）。選挙の前も、上の帯の任期の残りを押すと、同じ表で今の見込みを見られる（8 週前からは知らせも出る）
- 得票率（大きな数字と 50% の線）・層ごとの支持と投票率（12 層を 4×3 の表。行が年齢の帯、列が収入の帯。色の濃さが支持、文字が投票率）・得票に効いた層の上位 3 つ
- 結果: 当選なら次の任期へ（公約を選ぶ。10.7 の後）。落選なら敗因（層・要因の内訳・原因になった決定。押すとその場所へ）と、2 つの道（同じ都市で再び立つ・新しい都市で始める。`docs/game-design.md` 21.2）。どちらにも「学習の記録は消えない」と添える

### 10.7 任期の終わりの一覧

- 選挙の画面の次に開く。その 4 年の功績を、数字と都市の場所で示す（`docs/game-design.md` 21.3）: 完成した建物（押すとそこへ）・可決と否決の数・人口・雇用・財政・支持率の始めと終わり（小さな線のグラフ）・果たした公約・達成したミッション・その任期に修了したレッスンと上がったスキル
- 当選した時と、同じ都市で再び立つ時は、続けて次の任期の公約を 2 つ選ぶ（候補を一覧で。果たす条件と今の値を添える）

### 10.8 受信箱（請願）

- 届いた請願を 1 通ずつ（最大 5 通）: 送った集団（層と地区）・要望の文・届いた理由の模擬の値（「北浜地区の低い収入の世帯の家賃の負担が 37%」）・期限
- 手は 受理・拒否・保留 の 3 つ。受理の効き（財政の費用・模擬への効き）と、拒否した時に下がる信頼を、押す前に示す
- 押すと、その地区へカメラが寄る

### 10.9 予算

- 今週の収支: 収入（住民の税・事業者の税）と支出（公共サービスの維持・発電所の維持・外からの電気・請願）を、項ごとの数と短い棒で
- 税率: 5〜20% のつまみ（1% ずつ）。動かすと、見込みの税収の増減と、満足の「税」の点の増減を、層ごとに示す。決めると次の週から効く
- 財政の残りと、直近 52 週のグラフ（11.2 と同じ部品）
- 開発資金は別の財布であることを 1 行で示す（「開発資金は学習で増える。ここでは使わない」。`docs/game-design.md` 2 章）
- 政治資本のつまみ: 今の値・上限・この任期の得と使い（公約・ミッション・支持率の上昇・押し切り・説得・申し立ての抑え）

### 10.10 市内新聞

- 名前は「市民新報」。最新の号を上に、見出し（22px）と本文 2〜3 行。HUD の窓のまま（紙の模様を敷かない。`docs/visual-design.md` 4 章）
- 過去の記事を週ごとにさかのぼれる。見出しで探せる
- 記事を押すと、その場所へカメラが寄る

### 10.11 褒賞の一覧

- 褒賞の建物を 5 つ（`docs/game-design.md` 25 章）: 名前・節目の条件と今の値（「人口 3,420 / 5,000」）・効き・建てたか
- 届いた物は「建てる」で建設メニューのその建物を選んだ状態になる

### 10.12 始め方の選択

- 新しく始める時（初回・設定の「最初からやり直す」・落選の後の「新しい都市で始める」）に、都市画面の上の大きな窓で出す（初回も都市が後ろに見える。起動直後の主画面は都市画面のまま）
- 3 つ（穏やかな町・ふつう・手ごわい町）を横に並べ、違い（反対の組織化・申し立ての境・初めの政治資本）を数で示す。既定は「ふつう」で、選ばずに閉じてもふつうで始まる
- 初回の操作説明（9 章）は、この窓の後に出す。説明に市政（申請の看板・上の帯の支持率・市政の入口）を足す

## 11. 表示切替の窓

`docs/game-design.md` 14 章の仕組みの画面。小さな窓（10.0）。

### 11.1 ヒートマップ

- 表示の一覧: 学習の進み・人口・交通・発展段階（今あるもの）／ 地価・家賃・人口の密度・騒音・雇用・公共サービスの行き届き（警察・消防・学校・診療所・公園・平均）・電力・催し（競技場から 15 マス以内の住宅。届く・届かない）・支持率
- 選ぶと都市の地面に色を重ねる（建物は薄くして色を見せる）。凡例は右下の表示切替の帯に、値の幅と単位を出す（「家賃 4〜11 万円／月」）
- 色は tokens の値だけ（`docs/visual-design.md` 3 章）。良い向きを `state.ok`、悪い向きを `state.bad` に寄せた段階の色（5 段）。色だけに頼らず、マスを指すと値と単位を小窓で出す
- 公共サービスの行き届きでは、施設を押すと、その施設の届く範囲を縁で示す

### 11.2 グラフ

- 人口・開発資金・財政・支持率・雇用（仕事の数と失業率）の 5 本を、つまみで切り替える。横は週（直近 1 任期。それより前は 4 週ごとの点）、縦は値と単位
- 申請の可決・完成・税率の変更・選挙の週に小さな印。印を指すと何があったかを出す（因果を見るため）

### 11.3 平易な言葉の説明

- 窓の上に、支持率の「なぜ」を 1〜2 行（`docs/game-design.md` 14 章）。数字は太く
- 押すと、原因の場所へカメラが寄り、その要因のヒートマップに切り替わる
- 支持率が 4 週で 3 以上動いた時は、同じ文を知らせ（3 章）にも出す

### 11.4 需要（RCI）

- 建設メニューで区画の道具を選んだ時、引き出しの中に 3 本の棒（住宅・商業（店とオフィスに分ける）・工業）を出す（`docs/game-design.md` 23 章）。−100〜+100、0 の線
- 棒を押すと、その需要の内訳（項ごとの数）を小窓で出す
- 常時の UI には足さない（建設メニューの引き出しは、開いた時だけ出る物）

### 11.5 電力と公共サービスの建設と行き届き

- 建設メニューに「公共」の引き出しを足す: 警察署・消防署・学校・診療所・火力の発電所・太陽光の発電所・褒賞の建物（届いた物だけ）。財布（財政）と費用を出す
- 公共の道具を選んでいる間は、その種類の今の行き届き（電力なら来ている所と止まった所）のヒートマップを自動で重ね、置く場所の枠に、増える行き届きの範囲を縁で示す
- 発電所を選んでいる間は、上の帯の下に、今の電力の使う量と作る量（MW）を 1 行で出す（道具を離すと消える）
