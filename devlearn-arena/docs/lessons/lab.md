### lab.i.01 Web サービスを公開する（総合・中級）
- 解説: 何か=サーバの用意から HTTPS 公開までを通して行う課題 ｜ なぜ=個々の知識を、仕事の単位で使えるようにする ｜ 何に=実務の最初の一歩 ｜ 場面=新しいサービスを公開して、と頼まれた
- 図: サーバ → Web サーバ → ポートと規則 → 名前 → 証明書 → 公開
- 理解: [並べ替え] 作業を依存の順に並べる ／ [用語] 各作業と分野を結ぶ
- クイズ: [並べ替え] 作業の順 ／ [状況判断] HTTPS が警告 → 証明書の連鎖 ／ [原因特定] 外から届かない → 規則か待ち受け
- 実戦（端・編）: 目的=模擬サーバに Web を立て、ポートを開け、TLS を設定し、名前で開けるようにする ／ 達成=名前で HTTPS の 200・警告なし・再起動後も動く ／ ヒント=段ごとに 3 段 ／ エラー=段ごとの想定エラー（各分野の errorGuides を使う）
- 結果: 成功=研究施設の発表会で成果が都市に展示される ／ 未達=止まった段を示す
- まとめ: ①依存の順に組む ②各段で確かめる ③最後に通しで確かめる ／ 次: lab.i.02

### lab.a.01 コンテナ化して Kubernetes へ（総合・上級）

- 図: Dockerfile → イメージ → レジストリ → Deployment → Service → Ingress → 更新
- 理解: [並べ替え] 作業の順 ／ [関係性] 各部品の役割

### lab.a.03 新しい技術を調べて試す（総合・上級）
- 解説: 何か=公式の文書を読み、小さく試し、報告する一連の動き ｜ なぜ=技術は変わり続ける。調べて身に付ける力が要る ｜ 何に=新しい技術の導入・自分の成長 ｜ 場面=新しい道具を使うか判断して、と頼まれた
- 図: 問い → 公式の文書 → 小さく試す → 結果 → 報告
- 理解: [並べ替え] 調べる順 ／ [状況説明] 信頼できる情報の選び方

- 結果: 成功=研究施設に研究の成果が並ぶ ／ 未達=足りない項目を示す
- まとめ: ①公式の文書から ②小さく試す ③結果と判断を報告 ／ 次: —（自由に次の分野へ）
