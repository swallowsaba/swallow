# レッスン設計: Docker（docker）— コンテナ施設（Docker 工房）

書式は `docs/lessons/README.md`。コンテナの概念は `ctr.md`。ここでは Docker を**具体的な道具の 1 つ**として扱う。

### docker.b.01 Docker とは（Engine・初級）
- 解説: 何か=コンテナを作り・動かし・配る道具。Docker Engine（裏で動く本体）と CLI（命令する側）からなる ｜ なぜ=コンテナを扱う代表的な道具で、多くの現場で使われる ｜ 何に=開発・配布 ｜ 場面=手順書に docker run と書いてある
- 図: CLI → Engine → ランタイム → コンテナ。他の道具（Podman など）との並び
- 理解: [図] CLI と Engine を押す ／ [はい・いいえ] コンテナ技術 ＝ Docker → いいえ
- クイズ: [用語] Docker Engine → 裏で動く本体 ／ [原因特定] Cannot connect to the Docker daemon → Engine が動いていない ／ [選択] Docker の位置 → コンテナを扱う道具の 1 つ
- 実戦（端）: 目的=docker ps が「Cannot connect to the Docker daemon」で止まる dev-01 で、CLI と本体（Engine）を切り分けて本体を動かし、中のコンテナの様子を読む ／ 達成=①docker version で CLI の版（27.3.1）を答える ②docker のサービスが active ③docker info の Running（3）を答える ／ ヒント=①docker version の Client と Server の段 ②systemctl status docker と sudo systemctl start docker ③docker info の Running の行 ／ エラー=Cannot connect to the Docker daemon→原因候補「Engine（docker のサービス）の停止」
- 結果: 成功=Docker の構成を理解 ／ 未達=構成図を示す
- まとめ: ①Docker はコンテナの道具 ②CLI と Engine ③ほかの道具もある ／ 次: docker.b.02

### docker.b.02 イメージを取る・見る（image・初級）
- 解説: 何か=pull でレジストリから取り、images で一覧する ｜ なぜ=動かす前に設計図を手元に用意する ｜ 何に=公式のイメージの利用 ｜ 場面=nginx を動かしたい
- 図: レジストリ → pull → 手元の一覧
- 理解: [図] 一覧の名前・タグ・大きさの欄 ／ [関係性] タグの指定
- クイズ: [選択] 取る → docker pull ／ [結果予測] タグを省く → latest ／ [状況判断] 版を固定 → タグを指定
- 実戦（端）: 目的=nginx の 1.27 を取り、一覧で確かめる ／ 達成=一覧にある ／ ヒント=①取る ②タグ ③docker pull nginx:1.27 ／ エラー=not found→原因候補「タグの綴り」
- 結果: 成功=指定の版を取れた ／ 未達=一覧を示す
- まとめ: ①pull で取る ②images で見る ③版はタグで固定 ／ 次: docker.b.03

### docker.b.03 コンテナを動かす（run・初級）
- 解説: 何か=run で動かし、ps で見て、stop と rm で止めて消す ｜ なぜ=コンテナの一生を扱う基本 ｜ 何に=全ての作業 ｜ 場面=動かしたコンテナがどこにあるか分からない
- 図: run → 動作中 → stop → 停止 → rm → 消える
- 理解: [並べ替え] 一生の順 ／ [関係性] ps と ps -a
- クイズ: [結果予測] -d → 裏で動く ／ [状況判断] 止まった物も見る → ps -a ／ [原因特定] 名前が使われている → 同じ名前の物が残っている
- 実戦（端）: 目的=web という名前で nginx を裏で動かし、止めて消す ／ 達成=作成・停止・削除が記録される ／ ヒント=①名前と裏 ②止めて消す ③3 つのコマンド ／ エラー=Conflict→原因候補「同名が残る」
- 結果: 成功=一生を扱えた ／ 未達=状態の遷移を示す
- まとめ: ①run で動かす ②ps で見る ③stop と rm ／ 次: docker.b.04, docker.b.05

### docker.b.04 ポートを公開する（公開・初級）
- 解説: 何か=コンテナの中の待ち受けを、外の入口に結ぶこと ｜ なぜ=コンテナは閉じた箱で、そのままでは外から届かない ｜ 何に=Web を外に見せる ｜ 場面=起動したのにブラウザで開けない
- 図: -p 8080:80 の左右の対応
- 理解: [図] 外と中のポートを結ぶ ／ [用語] 左右の意味
- クイズ: [結果予測] -p 無し → 外から届かない ／ [原因特定] port is already allocated → 外のポートが使用中 ／ [状況判断] 2 つ目の Web → 別の外ポート
- 実戦（端）: 目的=web を 8080 番で見えるようにする ／ 達成=外から 8080 で応答 ／ ヒント=①今の公開 ②外:中 ③docker run -d -p 8080:80 nginx ／ エラー=使用中→原因候補「同じ外ポート」
- 結果: 成功=扉を付けられた ／ 未達=対応を示す
- まとめ: ①外:中 ②同じ外ポートは 1 つ ③待ち受けと公開の両方を確かめる ／ 次: docker.b.05, docker.i.04

### docker.b.05 ログと中に入る（観察・初級）
- 解説: 何か=logs で出力を見て、exec で中でコマンドを打つ ｜ なぜ=動かない時に中の様子を確かめる ｜ 何に=調査 ｜ 場面=コンテナがすぐ止まる
- 図: コンテナの標準出力 → logs、外から中へ → exec
- 理解: [関係性] logs と exec ／ [はい・いいえ] 止まったコンテナにも exec できる → いいえ
- クイズ: [選択] 出力を見る → docker logs ／ [状況判断] 中の設定を確かめる → exec ／ [原因特定] すぐ止まる → logs の最後
- 実戦（端）: 目的=すぐ止まるコンテナのログから原因を答える ／ 達成=正しい原因 ／ ヒント=①ps -a ②logs ③最後の誤りの行 ／ エラー=答えが違う→原因候補「最初の起動の行を見た」
- 結果: 成功=中の様子を確かめた ／ 未達=ログを示す
- まとめ: ①logs で出力 ②exec で中へ ③止まった物は logs ／ 次: docker.a.02

### docker.i.01 Dockerfile を書く（Dockerfile・中級）
- 解説: 何か=イメージの作り方を書いたファイル ｜ なぜ=同じイメージを誰でも何度でも作れる ｜ 何に=自分のアプリのイメージ ｜ 場面=作ったアプリをコンテナにしたい
- 図: FROM → COPY → RUN → CMD の流れと、それぞれの層
- 理解: [並べ替え] 書く順 ／ [用語] 命令と役割を結ぶ
- クイズ: [選択] 土台 → FROM ／ [結果予測] RUN → 作る時に実行 ／ [状況判断] 起動時の命令 → CMD
- 実戦（編）: 目的=小さな Web アプリのイメージを作る Dockerfile を書く ／ 達成=作ったイメージで 200 ／ ヒント=①土台 ②コピーと準備 ③完成した Dockerfile ／ エラー=起動しない→原因候補「CMD の誤り」
- 結果: 成功=作り方を書けた ／ 未達=誤りの行を示す
- まとめ: ①作り方をファイルに ②命令ごとに層 ③起動は CMD ／ 次: docker.i.02, docker.a.01

### docker.i.02 ビルドとタグ（build・中級）
- 解説: 何か=build でイメージを作り、tag で名前と版を付ける ｜ なぜ=版を区別して配布・戻しに備える ｜ 何に=リリース ｜ 場面=どのイメージが本番の物か分からない
- 図: Dockerfile → build → shop/web:1.2
- 理解: [関係性] 名前とタグ ／ [はい・いいえ] 同じタグに別の中身を上書きしてよい → 避けるべき
- クイズ: [選択] 作って名前を付ける → build -t ／ [状況判断] 本番の版 → 固有のタグ ／ [原因特定] 古い物が動く → タグの使い回し
- 実戦（端）: 目的=イメージを作り 1.2 と付け、一覧で確かめる ／ 達成=shop/web:1.2 がある ／ ヒント=①作る ②名前 ③docker build -t shop/web:1.2 . ／ エラー=Dockerfile が無い→原因候補「場所の誤り」
- 結果: 成功=版を付けて作れた ／ 未達=一覧を示す
- まとめ: ①build で作る ②タグで版 ③使い回さない ／ 次: docker.i.05

### docker.i.03 ボリューム（volume・中級）
- 解説: 何か=Docker でデータを残す領域 ｜ なぜ=コンテナを作り直してもデータを残す ｜ 何に=DB ｜ 場面=DB のコンテナを更新したらデータが消えた
- 図: 名前付きボリュームとコンテナの付け外し
- 理解: [関係性] ボリュームとコンテナの寿命 ／ [状況説明] 付けた場所の誤り
- クイズ: [結果予測] ボリューム付きで作り直す → データが残る ／ [選択] 作る → docker volume create ／ [原因特定] 消えた → 付けた場所が違う
- 実戦（端）: 目的=DB にボリュームを付け、作り直してもデータが残ることを確かめる ／ 達成=残る ／ ヒント=①作る ②付ける ③-v の指定 ／ エラー=消える→原因候補「中の場所の誤り」
- 結果: 成功=データを残せた ／ 未達=付けた場所を示す
- まとめ: ①残す物はボリューム ②付ける場所を正しく ③作り直しで確かめる ／ 次: docker.i.06

### docker.i.04 ネットワーク（network・中級）
- 解説: 何か=自分で作る網と、名前で届く仕組み ｜ なぜ=コンテナどうしを安全につなぐ ｜ 何に=Web と DB ｜ 場面=Web から DB に届かない
- 図: 自作の網に 2 つ。名前で届く
- 理解: [関係性] 同じ網・名前 ／ [はい・いいえ] 既定の網でも名前で届く → いいえ（自作の網なら届く）
- クイズ: [原因特定] 届かない → 網が違う ／ [選択] 作る → docker network create ／ [結果予測] 同じ網の db → 名前で届く
- 実戦（端）: 目的=網を作り、web から db に名前で届くようにする ／ 達成=届く ／ ヒント=①作る ②参加させる ③--network の指定 ／ エラー=名前が引けない→原因候補「既定の網にいる」
- 結果: 成功=名前でつないだ ／ 未達=網の図を示す
- まとめ: ①網を作る ②同じ網に入れる ③名前で届く ／ 次: docker.i.06

### docker.i.05 レジストリに置く（registry・中級）
- 解説: 何か=push でレジストリに置き、別の機械で pull する ｜ なぜ=作った物をどこからでも使える ｜ 何に=配布 ｜ 場面=本番のサーバに自分のイメージを届けたい
- 図: 手元 → push → レジストリ → pull → 本番
- 理解: [並べ替え] ログイン → タグ → push ／ [関係性] レジストリの名前とタグ
- クイズ: [原因特定] denied → 認証か権限 ／ [状況判断] 置き場所の名前 → レジストリの住所を含める ／ [結果予測] 本番で pull → 同じ物
- 実戦（端）: 目的=1.2 をレジストリに置き、別の機械で取って動かす ／ 達成=本番で動く ／ ヒント=①ログイン ②名前 ③push と pull ／ エラー=denied→原因候補「ログインしていない」
- 結果: 成功=配れた ／ 未達=止まった段を示す
- まとめ: ①push で置く ②pull で取る ③名前に住所を含める ／ 次: cicd.b.04

### docker.i.06 Compose で複数コンテナ（Compose・中級）
- 解説: 何か=複数のコンテナの構成を 1 つのファイルに書いて一度に動かす ｜ なぜ=長いコマンドを毎回打たずに、構成を共有できる ｜ 何に=開発環境・小さな本番 ｜ 場面=Web と DB を毎回手で動かしている
- 図: compose.yaml の services・ports・volumes・networks
- 理解: [図] 各部分を押す ／ [関係性] サービス名と網の名前
- クイズ: [選択] 一度に動かす → docker compose up ／ [結果予測] 同じファイルの中 → 名前で届く ／ [原因特定] 起動順の問題 → 準備を待つ設定
- 実戦（編）: 目的=Web と DB を compose.yaml で動かす ／ 達成=Web が DB を使って 200 ／ ヒント=①2 つのサービス ②ポートとボリューム ③完成したファイル ／ エラー=DB に届かない→原因候補「localhost を指した」
- 結果: 成功=構成をファイルにできた ／ 未達=誤りの行を示す
- まとめ: ①構成を 1 ファイルに ②一度に動かす ③サービス名で届く ／ 次: k8s.b.01

### docker.a.01 マルチステージビルド（軽量化・上級）
- 解説: 何か=作る段と動かす段を分け、動かすのに要る物だけを最後の段に入れる ｜ なぜ=小さく安全なイメージにする ｜ 何に=本番のイメージ ｜ 場面=イメージが 1GB ある
- 図: 作る段（道具が多い）→ 成果物だけ → 動かす段（小さい）
- 理解: [関係性] 段と含まれる物 ／ [状況説明] 道具を残す危険
- クイズ: [結果予測] 作る道具 → 最後のイメージに入らない ／ [状況判断] 小さくしたい → マルチステージ ／ [原因特定] 大きいまま → 最後の段の土台が大きい
- 実戦（編）: 目的=1GB のイメージを 100MB 以下にする ／ 達成=大きさが基準以下で動く ／ ヒント=①段を分ける ②成果物のコピー ③完成した Dockerfile ／ エラー=動かない→原因候補「実行に要る物を写し忘れた」
- 結果: 成功=小さくできた ／ 未達=中身の比較を示す
- まとめ: ①段を分ける ②要る物だけ ③小さいほど安全 ／ 次: cicd.a.02

### docker.a.02 起動しないコンテナを直す（障害・上級）
- 解説: 何か=終了コード・ログ・設定から原因を特定する ｜ なぜ=コンテナは失敗するとすぐ止まり、原因が見えにくい ｜ 何に=障害対応 ｜ 場面=起動直後に Exited (1)
- 図: ps -a の終了コード → logs → inspect → 直す
- 理解: [並べ替え] 調べる順 ／ [用語] 終了コードの意味（0・1・137）
- クイズ: [原因特定] 137 → 強制終了（メモリ不足など） ／ [原因特定] 1 → アプリの失敗 ／ [状況判断] 設定を見る → inspect ／ [用語] 終了コード 0 → 正常に終わった
- 実戦（端）: 初期=環境変数の不足とメモリの上限不足が重なる ／ 目的=2 つ直して動かす ／ 達成=動き続ける ／ ヒント=①終了コード ②ログと設定 ③2 つの直し方 ／ エラー=また止まる→原因候補「2 つ目が残る」
- 結果: 成功=原因を特定して直した ／ 未達=残る原因を示す
- まとめ: ①終了コードから推測 ②ログと設定 ③1 つずつ直して確かめる ／ 次: trouble.a.01

### docker.a.03 Docker 以外の道具（周辺・上級）
- 解説: 何か=Podman・BuildKit など、同じ標準に沿う別の道具 ｜ なぜ=道具は入れ替えられる。標準を理解していれば困らない ｜ 何に=環境に合わせた選択 ｜ 場面=Docker が使えない環境で作業する
- 図: 同じイメージを複数の道具で作り・動かす
- 理解: [関係性] 標準と道具 ／ [はい・いいえ] Podman で作ったイメージは Docker で動かない → いいえ
- クイズ: [選択] 共通の標準 → OCI ／ [状況判断] 常駐する本体を置きたくない → Podman ／ [結果予測] 道具を変える → イメージはそのまま使える
- 実戦（模）: 目的=同じイメージを別の道具で動かし、結果が同じことを確かめる ／ 達成=同じ応答 ／ ヒント=①命令の対応 ②同じイメージ ③コマンド ／ エラー=動かない→原因候補「権限の違い」
- 結果: 成功=道具に依存しない理解 ／ 未達=命令の対応表を示す
- まとめ: ①標準があるから入れ替えられる ②命令はよく似ている ③Docker は道具の 1 つ ／ 次: k8s.b.03
