### net.b.01 ネットワークとは（LAN と WAN）（全体像・初級）
- 解説: 何か=近くの機械をつなぐ LAN と、離れた LAN どうしをつなぐ WAN ｜ なぜ=どこまでが自分の網かで、調べる所が変わる ｜ 何に=会社と支店・家とインターネット ｜ 場面=社内の共有フォルダは見えるのに外のサイトが見えない
- 図: 家の LAN・会社の LAN と、それをつなぐ WAN
- 理解: [図] LAN と WAN の範囲を塗る ／ [関係性] ルータの役割 → 網と網をつなぐ
- クイズ: [用語] LAN → 近くをつなぐ網 ／ [原因特定] 社内は見えるが外が見えない → LAN の外への出口 ／ [選択] 網と網をつなぐ機器 → ルータ
- 実戦（模）: 目的=2 つの LAN をつなぎ、支店から本社のサーバに届かせる ／ 達成=通信が届く ／ ヒント=①網の境目 ②網と網をつなぐ機器 ③両方の LAN をルータにつなぐ ／ エラー=届かない→原因候補「ルータを置いていない」
- 結果: 成功=網の範囲を説明できた ／ 未達=途切れた箇所を示す
- まとめ: ①LAN は近く、WAN は遠く ②ルータが網をつなぐ ③どの範囲の問題かを先に考える ／ 次: net.b.02

### net.b.02 OSI と TCP/IP の層（層・初級）
- 解説: 何か=通信の仕事を層に分けて考える型 ｜ なぜ=問題がどの層かで、見る所と道具が決まる ｜ 何に=障害の切り分け・技術の位置付け ｜ 場面=線はつながっているのに Web が開かない
- 図: 4 層（リンク・インターネット・トランスポート・アプリケーション）と OSI 7 層の対応、各層の例（イーサネット・IP・TCP・HTTP）
- 理解: [並べ替え] 下の層から順に ／ [用語] IP・TCP・HTTP を層に結ぶ
- クイズ: [選択] HTTP の層 → アプリケーション ／ [状況判断] ping は届くが Web が開かない → IP より上の層 ／ [原因特定] 線が抜けた → 一番下の層
- 実戦（模）: 目的=5 つの症状を、原因の層に仕分ける ／ 達成=全て正しい ／ ヒント=①下から順に ②届くかどうかは IP ③仕分けの答え ／ エラー=取り違え→原因候補「TCP と HTTP を同じ層と見た」
- 結果: 成功=層で考えられた ／ 未達=症状と層の対応を示す
- まとめ: ①通信は層の積み重ね ②下から確かめる ③層ごとに道具が違う ／ 次: net.b.03

### net.b.03 IP アドレスとサブネット（IP・初級）
- 解説: 何か=網の中の機械の住所（IP アドレス）と、網の範囲（サブネット） ｜ なぜ=同じ網か違う網かで、直接届くかが決まる ｜ 何に=サーバの設定・網の設計 ｜ 場面=192.168.1.10 と 192.168.2.10 が直接通信できない
- 図: 192.168.1.10/24 をネットワーク部とホスト部に分ける
- 理解: [図] /24 の区切りの位置を示す ／ [はい・いいえ] 192.168.1.5/24 と 192.168.1.200/24 は同じ網 → はい
- クイズ: [結果予測] /24 の網に置ける機械の数の目安 → 254 ／ [状況判断] 違う網に届けたい → ルータを通す ／ [用語] プライベートアドレス → 網の中だけで使う住所
- 実戦（模）: 目的=4 台の機械に、同じ網になるアドレスを振る ／ 達成=4 台が互いに届く ／ ヒント=①網の部分を揃える ②/24 なら前の 3 つ ③192.168.10.11〜14/24 ／ エラー=届かない機械→原因候補「網の部分が違う」「同じアドレスが重なった」
- 結果: 成功=網の範囲を作れた ／ 未達=重なりと食い違いを示す
- まとめ: ①IP は住所 ②/ の数が網の範囲 ③違う網はルータで ／ 次: net.b.04, net.b.06

### net.b.04 ポート（ポート・初級）
- 解説: 何か=1 台の機械の中で、どのプログラムに届けるかを示す番号 ｜ なぜ=1 台で Web・SSH・DB を同時に動かす ｜ 何に=サービスの公開・ファイアウォール ｜ 場面=Web は 80 番、SSH は 22 番
- 図: 1 つの建物（IP）に並ぶ扉（ポート）と、扉ごとの担当
- 理解: [関係性] IP とポート → 建物と扉 ／ [用語] 22・80・443 と担当を結ぶ
- クイズ: [選択] HTTPS の既定 → 443 ／ [原因特定] サーバは動くがつながらない → その扉が閉じている ／ [結果予測] 同じポートで 2 つ待とうとする → 2 つ目が失敗
- 実戦（模）: 目的=3 つのサービスを正しい扉につなぐ ／ 達成=全て届く ／ ヒント=①既定の番号 ②重ならない ③Web 80・HTTPS 443・SSH 22 ／ エラー=address already in use→原因候補「同じ扉を 2 つに割り当てた」
- 結果: 成功=扉で届け分けられた ／ 未達=重なりを示す
- まとめ: ①ポートは扉 ②既定の番号を覚える ③1 つの扉に 1 つのプログラム ／ 次: net.b.05, net.i.03

### net.b.05 TCP と UDP（TCP/UDP・初級）
- 解説: 何か=届いたか確かめながら送る TCP と、確かめずに速く送る UDP ｜ なぜ=用途で確実さと速さのどちらを取るかが違う ｜ 何に=Web は TCP、音声や DNS の問い合わせは UDP ｜ 場面=通話で少し途切れても遅れないほうがよい
- 図: TCP（確認の返事あり）と UDP（送りっぱなし）の往復の比較
- 理解: [関係性] 確実さと速さの交換 ／ [用語] TCP・UDP と特徴を結ぶ
- クイズ: [状況判断] ファイルの転送 → TCP ／ [状況判断] 生の音声 → UDP ／ [結果予測] UDP で一部が失われた → 送り直されない ／ [原因特定] 動画が少し乱れるが止まらない → UDP で一部が失われた
- 実戦（模）: 目的=4 つのサービスに TCP と UDP を選ぶ ／ 達成=全て理由付きで正しい ／ ヒント=①欠けて困るか ②遅れて困るか ③答え ／ エラー=取り違え→原因候補「速さだけで選んだ」
- 結果: 成功=使い分けられた ／ 未達=理由を並べて示す
- まとめ: ①TCP は確実 ②UDP は速い ③用途で選ぶ ／ 次: net.i.04

### net.b.06 名前解決（DNS・初級）
- 解説: 何か=名前を IP アドレスに変える仕組み ｜ なぜ=人は数字の住所を覚えられない ｜ 何に=Web・メール・API の接続先 ｜ 場面=IP なら開くのに名前では開かない
- 図: 端末 → 問い合わせ役 → 権威のあるサーバ、と答えが戻る流れ
- 理解: [並べ替え] 問い合わせの順 ／ [用語] キャッシュ → 一度引いた答えを覚えておく
- クイズ: [原因特定] IP では開くが名前では開かない → 名前解決 ／ [結果予測] dig +short shop.example → IP アドレス ／ [状況判断] 変更が反映されない → キャッシュの期限を待つ
- 実戦（端）: 目的=shop.example の IP を調べ、古い値を指す誤りを直す ／ 達成=正しい値に直り名前で届く ／ ヒント=①dig で引く ②期待との違い ③A レコードを正しい値に ／ エラー=まだ古い→原因候補「キャッシュ」
- 結果: 成功=名前と番号の対応を直せた ／ 未達=引いた答えと期待を並べる
- まとめ: ①DNS は名前と番号の対応表 ②dig で確かめる ③反映は遅れることがある ／ 次: web.b.01, net.i.05

### net.b.07 ping と traceroute（確認・初級）
- 解説: 何か=届くかを確かめる ping と、経路を確かめる traceroute ｜ なぜ=どこまで届いているかが分かれば原因の場所が絞れる ｜ 何に=切り分けの最初の一手 ｜ 場面=サーバにつながらない
- 図: 往復の時間と、途中の機器を順に示す経路
- 理解: [関係性] ping と traceroute の違い ／ [状況説明] 3 つ目の機器で止まる経路の意味
- クイズ: [結果予測] ping が全て失敗 → 届かないか、応答を止めている ／ [原因特定] traceroute が途中で止まる → その先の区間 ／ [状況判断] 届くのに遅い → 往復の時間を見る
- 実戦（端）: 目的=届かない原因の区間を特定する ／ 達成=正しい区間を回答 ／ ヒント=①まず ping ②経路を見る ③止まった機器の次の区間 ／ エラー=答えが違う→原因候補「応答しない機器を壊れていると判断」
- 結果: 成功=区間まで絞れた ／ 未達=経路の読み方を示す
- まとめ: ①ping で届くか ②traceroute で経路 ③応答しない機器もある ／ 次: net.i.01, trouble.b.01

### net.b.08 DHCP（DHCP・初級）
- 解説: 何か=網に入った機械にアドレスを自動で配る仕組み ｜ なぜ=手で 1 台ずつ設定すると重なりと手間が生まれる ｜ 何に=PC・スマホの接続 ｜ 場面=新しい PC を網につなぐと自動で使える
- 図: 「アドレスください」→「これを使って」の 4 往復
- 理解: [並べ替え] 4 往復の順 ／ [はい・いいえ] サーバのアドレスも DHCP に任せるのがよい → いいえ（固定にするのが一般的）
- クイズ: [用語] リース → 一定期間の貸し出し ／ [原因特定] 169.254 で始まるアドレス → DHCP から受け取れていない ／ [状況判断] 配る数が足りない → 範囲を広げる
- 実戦（模）: 目的=配る範囲を設定し、5 台にアドレスを配る ／ 達成=5 台が重ならず受け取る ／ ヒント=①範囲 ②固定の機械と重ならない ③.100〜.150 を配る ／ エラー=重なり→原因候補「固定のアドレスを範囲に含めた」
- 結果: 成功=自動で配れた ／ 未達=重なりを示す
- まとめ: ①DHCP は自動で配る ②貸し出しには期限 ③サーバは固定が多い ／ 次: net.i.01

### net.i.01 経路とデフォルトゲートウェイ（ルーティング・中級）
- 解説: 何か=どの宛先へどの出口から送るかの表（経路表）と、知らない宛先の出口（デフォルトゲートウェイ） ｜ なぜ=網をまたぐ通信は経路が無いと迷う ｜ 何に=網の設計・つながらない時の確認 ｜ 場面=社内は届くが外に出られない
- 図: 経路表の 3 行と、宛先ごとの行き先
- 理解: [図] 宛先から使う行を選ぶ ／ [関係性] デフォルトの経路 → 他に当てはまらない時の出口
- クイズ: [原因特定] 外にだけ出られない → デフォルトゲートウェイが無い ／ [結果予測] 10.0.2.5 宛て → 10.0.2.0/24 の行 ／ [状況判断] 新しい網へ → 経路を足す
- 実戦（模）: 目的=経路表に足りない行を足し、3 つの網を互いに届くようにする ／ 達成=全ての組み合わせで届く ／ ヒント=①届かない組み合わせ ②戻りの経路も要る ③足す 2 行 ／ エラー=片道だけ→原因候補「戻りの経路が無い」
- 結果: 成功=経路を設計できた ／ 未達=届かない組み合わせを示す
- まとめ: ①経路表で出口を決める ②知らない宛先はデフォルトへ ③戻りの経路も要る ／ 次: net.i.02, net.i.06

### net.i.02 NAT（NAT・中級）
- 解説: 何か=網の中の住所を外向きの住所に付け替える仕組み ｜ なぜ=外向きの住所は少なく、中の住所は外では使えない ｜ 何に=家庭や会社からインターネットへ・サーバの公開 ｜ 場面=中のサーバを外に公開したいのに届かない
- 図: 中の 192.168.1.10 が外の 203.0.113.5 に付け替わる往復
- 理解: [関係性] 外へ出る付け替えと、外から入る転送の違い ／ [はい・いいえ] 中の住所は外から直接届く → いいえ
- クイズ: [原因特定] 外から公開サーバに届かない → 転送の設定が無い ／ [結果予測] 中の 3 台が外へ出る → 外からは同じ住所に見える ／ [状況判断] 外の 8080 を中の 80 へ → 転送の規則
- 実戦（模）: 目的=外の 443 番を中の Web サーバへ転送し、公開する ／ 達成=外から届く ／ ヒント=①入ってくる方向の設定 ②外の番号と中の宛先 ③443 → 192.168.1.10:443 ／ エラー=届かない→原因候補「宛先の住所の誤り」「ファイアウォールで閉じている」
- 結果: 成功=付け替えと転送を設定できた ／ 未達=付け替えの表を示す
- まとめ: ①NAT は住所の付け替え ②外から入れるには転送 ③ファイアウォールも確かめる ／ 次: net.i.03, cloud.b.03

### net.i.03 ファイアウォール（Firewall・中級）
- 解説: 何か=通してよい通信と止める通信の規則 ｜ なぜ=必要な扉だけ開け、それ以外を閉じる ｜ 何に=サーバの防御・公開範囲の制御 ｜ 場面=Web を公開したのに外から届かない
- 図: 規則が上から順に評価され、最初に当てはまった物で決まる
- 理解: [並べ替え] 規則の評価の順 ／ [状況説明] 最後の「全て拒否」の意味
- クイズ: [原因特定] 公開したのに届かない → 許可の規則が無い ／ [結果予測] 拒否が許可より上にある → 拒否される ／ [状況判断] SSH を社内だけから → 送り元を絞って許可
- 実戦（模）: 目的=Web（80・443）を全員に、SSH を社内の網だけに許可する ／ 達成=条件通りに通る・止まる ／ ヒント=①必要な扉 ②送り元の指定 ③規則 3 行と最後の拒否 ／ エラー=SSH が外から通る→原因候補「送り元を絞っていない」
- 結果: 成功=必要最小限だけ開けた ／ 未達=どの規則に当たったかを示す
- まとめ: ①規則は上から ②必要な物だけ許可 ③送り元で絞る ／ 次: net.a.01, trouble.i.02

### net.i.04 接続の確立と状態（TCP・中級）
- 解説: 何か=TCP の接続を始める 3 回のやり取りと、接続の状態 ｜ なぜ=つながらない理由が、相手が居ないのか閉じているのかを見分けられる ｜ 何に=接続の障害の切り分け ｜ 場面=接続がたくさん残ってサーバが重い
- 図: SYN → SYN/ACK → ACK と、LISTEN・ESTABLISHED・TIME_WAIT
- 理解: [並べ替え] 3 回のやり取りの順 ／ [用語] 状態と意味を結ぶ
- クイズ: [原因特定] 拒否された（refused）→ その扉で待っていない ／ [原因特定] 時間切れ（timeout）→ 途中で止められているか相手が居ない ／ [結果予測] ss で ESTABLISHED → 通信中 ／ [状況判断] 接続を確かめる最初の道具 → ss で状態を見る
- 実戦（端）: 目的=接続の状態の一覧から、待ち受けていないサービスと、止められている経路を答える ／ 達成=両方正しい ／ ヒント=①refused と timeout ②LISTEN の有無 ③答え ／ エラー=取り違え→原因候補「refused を経路の問題と見た」
- 結果: 成功=状態で原因を分けた ／ 未達=状態の意味を示す
- まとめ: ①接続は 3 回のやり取りで始まる ②refused は待っていない ③timeout は途中か相手 ／ 次: net.a.02

### net.i.05 DNS レコード（DNS・中級）
- 解説: 何か=名前に結び付ける情報の種類（A・AAAA・CNAME・MX・TXT） ｜ なぜ=用途ごとに正しい種類を使わないと届かない ｜ 何に=サイトの公開・メールの受け取り・所有の証明 ｜ 場面=www だけ開けない
- 図: 5 種類のレコードと、それぞれの例
- 理解: [用語] 種類と用途を結ぶ ／ [関係性] CNAME は別名 → 別の名前を指す
- クイズ: [選択] メールの受け取り先 → MX ／ [原因特定] www だけ開けない → www のレコードが無い ／ [状況判断] 所有の証明の文字列 → TXT
- 実戦（模）: 目的=サイトとメールが届くようにレコードを整える ／ 達成=名前・www・メールが全て届く ／ ヒント=①足りない名前 ②種類 ③A と CNAME と MX ／ エラー=メールが届かない→原因候補「MX が無い」
- 結果: 成功=用途ごとに設定できた ／ 未達=足りないレコードを示す
- まとめ: ①種類ごとに用途がある ②別名は CNAME ③メールは MX ／ 次: sec.b.07

### net.i.06 ネットワークを分ける（設計・中級）
- 解説: 何か=網を用途ごとに分ける考え方（セグメント・VLAN） ｜ なぜ=問題の広がりを抑え、守る範囲をはっきりさせる ｜ 何に=社内・サーバ・来客用の分離 ｜ 場面=来客用の Wi-Fi から社内のサーバが見える
- 図: 1 つの網と、3 つに分けた網の比較
- 理解: [関係性] 分けた網どうしの通信 → ルータとファイアウォールを通る ／ [状況説明] 分けないと何が起きるか
- クイズ: [状況判断] 来客を社内から離す → 別の網にする ／ [用語] VLAN → 1 つの機器で網を分ける ／ [結果予測] 分けた網どうし → 規則で許した物だけ通る
- 実戦（模）: 目的=社内・サーバ・来客の 3 つに分け、来客から社内が見えないようにする ／ 達成=条件通り ／ ヒント=①3 つの網 ②間に規則 ③来客 → 社内を拒否 ／ エラー=見えてしまう→原因候補「同じ網に置いた」
- 結果: 成功=範囲を分けて守れた ／ 未達=つながってしまう経路を示す
- まとめ: ①用途で網を分ける ②間は規則で制御 ③問題の広がりを抑える ／ 次: k8s.b.07, cloud.i.01

### net.a.01 繋がらない原因を層ごとに探す（切り分け・上級）
- 解説: 何か=下の層から順に確かめ、原因の層を絞る方法 ｜ なぜ=思いつきで触ると時間を失う ｜ 何に=ネットワークの障害対応 ｜ 場面=「サービスにつながらない」という報告
- 図: 層ごとの確認の道具（リンク・ping・経路・ポート・名前・HTTP）
- 理解: [並べ替え] 確かめる順 ／ [状況説明] 結果から次の一手を選ぶ
- クイズ: [状況判断] ping は届く → 次はポートか名前 ／ [原因特定] 名前で届かず IP で届く → DNS ／ [原因特定] ポートが refused → サービスが待っていない ／ [結果予測] 経路を直した後 → ping が届き、次の層の確認に進める
- 実戦（模）: 初期=3 つの原因が重なる（経路・名前・ポート）／ 目的=順に解き、利用者が届くようにする ／ 達成=名前で HTTP 200 ／ ヒント=①下から ②段ごとの道具 ③3 つの直し方 ／ エラー=途中で届かない→原因候補「残りの層」
- 結果: 成功=層ごとに解けた ／ 未達=どの層が残っているかを示す
- まとめ: ①下の層から ②1 つ直したら確かめる ③重なった原因もある ／ 次: trouble.i.02, mon.i.03

### net.a.02 MTU と断片化（経路・上級）
- 解説: 何か=1 回で送れる大きさの上限（MTU）と、それを超えた時の分割 ｜ なぜ=小さな通信は通るのに、大きな通信だけ失敗する原因になる ｜ 何に=VPN やトンネルを使う網の障害 ｜ 場面=ページの一部だけ読み込めない
- 図: 経路の途中で上限の小さい区間と、そこで落ちる大きな荷物
- 理解: [関係性] 上限の小さい区間が 1 つあると → 全体がその上限になる ／ [状況説明] 大きな荷物だけ落ちる理由
- クイズ: [原因特定] 小さな通信は通り大きな物が止まる → MTU ／ [結果予測] 分割を禁止して上限を超える → 落ちる ／ [状況判断] 対策 → 送る大きさを合わせる
- 実戦（模）: 目的=大きな通信だけ失敗する区間を特定し、上限を合わせる ／ 達成=大きな通信が通る ／ ヒント=①大きさを変えて試す ②区間を絞る ③その区間に合わせた値 ／ エラー=まだ落ちる→原因候補「別の区間も小さい」
- 結果: 成功=大きさの問題を見抜けた ／ 未達=区間ごとの上限を示す
- まとめ: ①MTU は 1 回の上限 ②最も小さい区間で決まる ③大きな物だけ失敗する時に疑う ／ 次: web.a.01

### net.a.03 ロードバランサ（負荷分散・上級）
- 解説: 何か=来た通信を複数のサーバに振り分ける仕組み ｜ なぜ=1 台では足りない・1 台が壊れても止めない ｜ 何に=Web サービスの拡張と冗長化 ｜ 場面=アクセスが増えて 1 台では間に合わない
- 図: 入口 1 つから後ろの 3 台へ、健全な物にだけ振り分ける
- 理解: [関係性] 健全性の確認 → 壊れた物に送らない ／ [用語] 振り分けの方式と特徴を結ぶ
- クイズ: [状況判断] 1 台が壊れた → 健全性の確認で外す ／ [結果予測] 3 台に順番に振る → ほぼ均等 ／ [原因特定] ログインが途切れる → 同じ利用者が別の台へ
- 実戦（模）: 目的=3 台に振り分け、1 台を止めても応答が続くようにする ／ 達成=止めても 200 が続く ／ ヒント=①振り分け先 ②健全性の確認 ③確認の URL と間隔を設定 ／ エラー=止めた台に送る→原因候補「健全性の確認が無い」
- 結果: 成功=止まらない入口を作れた ／ 未達=振り分けの記録を示す
- まとめ: ①入口 1 つで複数へ ②健全な物だけに送る ③状態の扱いに注意 ／ 次: k8s.b.06, cloud.i.02

### net.a.04 IPv6 の基本（IPv6・上級）
- 解説: 何か=住所を大きく広げた新しい IP ｜ なぜ=IPv4 の住所が足りない ｜ 何に=これからの網・クラウド ｜ 場面=アドレスの欄に 2001:db8:: のような表記がある
- 図: 128 ビットの住所の書き方と省略の規則
- 理解: [用語] :: の意味 → 0 の連続の省略 ／ [関係性] IPv4 と IPv6 → 別の住所の体系
- クイズ: [結果予測] 2001:0db8:0000:0000:0000:0000:0000:0001 の省略 → 2001:db8::1 ／ [選択] IPv6 の名前の対応 → AAAA ／ [状況判断] 両方で公開 → A と AAAA の両方
- 実戦（模）: 目的=IPv6 でも届くようにアドレスとレコードを設定する ／ 達成=IPv6 で届く ／ ヒント=①アドレス ②名前の対応 ③AAAA を足す ／ エラー=届かない→原因候補「レコードが無い」
- 結果: 成功=新しい住所でも届けられた ／ 未達=足りない設定を示す
- まとめ: ①IPv6 は広い住所 ②:: で省略 ③名前は AAAA ／ 次: cloud.b.03
