# 都市デザイン

ゲームの規則と数値は `docs/game-design.md`、描画の技術は `docs/architecture.md`、色と字は `docs/visual-design.md`。
この文書は**都市の構造と、何がどう建ち、どう見えるか**を決める。
施設・公共サービス・発電所は、置くと申請になり、審議を経て建つ（`docs/game-design.md` 15 章）。その間の見た目は 9 章。

## 1. 都市構造

- 都市は等角投影（2:1）の格子の上にある。1 マス = 道路 1 本分の幅
- 地図は 96×96 マス。初めは中央の 24×24 マスが使える。発展段階で外側の霧が晴れる
- 地形: 浮いた島の地盤（厚みのある縁）・海・川（蛇行）・丘（高さ 0〜3 段の起伏）。海岸線と川は曲線で、階段状にしない
- 層: 地面 → 水 → 道路 → 区画の地面 → 建物と木 → 車と人 → 名札 → UI

## 2. 道路

| 種類 | 幅 | できる段階 | 見た目 |
|---|---|---|---|
| 細い道 | 1 マス | 村 | 路面・縁石・白線なし |
| 一般道 | 1 マス | 村 | 路面・縁石・中央線・横断歩道 |
| 大通り | 2 マス | 地方都市 | 中央分離帯と並木・車線 2 本ずつ |
| 橋 | — | 町 | 川を渡る所に自動で架かる。欄干と影 |
| ロータリー | 3×3 | 地方都市 | 環道と中央の緑地 |

- 道路はドラッグで引く。直線と、曲線（始点・制御点・終点）を引ける
- 交差点は自動でつなぐ。行き止まりには転回場を描く
- 建物と区画は、道路に面していないと機能しない（建たない）

## 3. 区画

学習者が塗る。中の建物は自動で建ち、育つ（`docs/decisions.md` D-03）。

| 区画 | 建つもの | 育ち方 |
|---|---|---|
| 住宅 | 戸建て → 低層集合住宅 → 中層 → 高層 | 雇用（オフィス・施設）と周辺の公園で育つ |
| 商業 | 小さな店 → 商店街 → 商業ビル | 人口で育つ |
| オフィス | 小さな事務所 → オフィスビル → 高層オフィス | 技術力で育つ |
| 工業 | 小さな作業場 → 工場と倉庫 → 大きな工場（煙突・荷さばきの車寄せ・積まれた荷） | 失業者と道路網の大きさで育つ。周りに騒音を出す |

- 区画の建物の中身（住む世帯・働く事業者）と育ち方の数値は `docs/game-design.md` 13・23 章（需要）。区画が育つことは申請にしない
- 人の住む住宅の建物から 3 マス以内に工業・商業・オフィスを塗る時と、既にある区画の種類を変える時は「用途地域の変更」の申請になる（`docs/game-design.md` 15.1）。可決するまで、塗った区画は破線の縁で示し、建物は建たない

## 4. 施設

学習者が置く。**施設は学習の入口であり、成果が形になる場所。学習を制限しない**（`docs/decisions.md` D-02）。
置くと申請になり、可決・着工・完成の後に動き出す（9 章）。申請中・工事中・停電中でも、施設を押せば情報パネルが開き、そこから学習を始められる。

| 施設 | 対応する分野 | 大きさ | 見た目の特徴（Lv が上がると加わるもの） |
|---|---|---|---|
| 市立 IT 学院 | IT 基礎 | 3×3 | 校舎と時計塔 → 図書館棟 → 講堂 |
| サーバ施設 | Linux | 2×2 | 平屋のサーバ棟と冷却塔 → 増築棟 → 発電設備 |
| ネットワークセンター | ネットワーク | 2×2 | 局舎と鉄塔 → アンテナ → 光ケーブルの地中線 |
| Web 施設 | Web / HTTP | 2×2 | ガラス張りの低層ビル → 看板 → 展望フロア |
| セキュリティセンター | TLS / セキュリティ | 2×2 | 堅牢な建物と門 → 監視カメラ → 塔 |
| 開発オフィス | Git | 2×2 | 中層のオフィス → 屋上庭園 → 渡り廊下 |
| デプロイセンター | CI/CD | 3×2 | 工場とベルトコンベア → 出荷口 → 自動倉庫 |
| コンテナ施設 | コンテナ / Docker | 3×3 | 港とクレーン、積まれたコンテナ → 倉庫 → 第二埠頭（Docker 工房） |
| クラスタ施設 | Kubernetes | 3×3 | 同じ形のビル群（ノード）と管制塔 → 棟の追加 → ヘリポート |
| データセンター | データベース | 3×2 | 窓の少ない大きな建物と空調 → 増設棟 → 予備電源 |
| クラウドセンター | クラウド / インフラ | 3×3 | 雲を模した屋根の建物 → 複数棟の分散 → 別地区の分館 |
| 監視・運用センター | 監視 | 2×2 | 大きな窓の管制室とアンテナ → 大型画面 → 塔 |
| DevOps 推進本部 | DevOps | 2×2 | 中層ビルと広場 → 連絡橋で他施設とつながる |
| インシデント対応本部 | トラブルシューティング | 2×2 | 消防署に似た建物と車庫 → 出動車両 → 指令塔 |
| 研究施設 | 研究（総合演習） | 3×3 | ドーム屋根の研究所 → 実験棟 → 展示ホール |

- レベル 1〜5。レベルごとに見た目を変える（上の「加わるもの」）。Lv1 と Lv5 は一目で違うこと
- 施設を押すと情報パネル（`docs/ui-design.md`）: 名前・レベル・状態（申請の段階・工事・稼働・停電）・対応する分野・関係するスキルの値・おすすめのレッスン・ミッション・アップグレード
- 公園・広場・並木・噴水・記念碑（ミッションの報酬）も置ける。これらは申請が要らない
- 施設は都市の模擬に、雇用・騒音・電力の使用・地価への効きを持つ（数値は `docs/game-design.md` 13・24 章）。公共サービスとの違いは 9.3

## 5. 発展段階と見た目

規則は `docs/game-design.md` の 6 章。見た目の変化をここで決める。

| 段階 | 見た目 |
|---|---|
| 1 村 | 細い道と戸建て。畑と木が多い。施設は小さな Lv1 |
| 2 町 | 一般道と橋。商店街。低層集合住宅。公園 |
| 3 地方都市 | 大通りとロータリー。中層ビル。施設が Lv3 で大きく |
| 4 中核都市 | 高層ビル群。鉄道（景観）。窓の数と細部が増える |
| 5 技術都市 | 超高層とランドマーク。施設群が連絡橋でつながる |

- 学習の直後に都市へ戻ったら、変化のあった場所へカメラが寄り、光の輪と名札で何が変わったかを示す
- 発展段階は、**完成して動いている**施設の Lv と人口で決まる（`docs/game-design.md` 2・6 章）。申請中・工事中の施設は数えない。段階は下がらず、一度晴れた霧は戻らない
- 申請・審議は発展段階を変えない。段階で開く物（大通り・中層・大型施設の Lv）は、今までどおり段階で開き、開いた後に申請として出す

## 6. 動き

- 車が道路を走り、人が歩道を歩く（数は都市規模に応じて増える）
- 施設ごとの動き: コンテナ施設のクレーン、デプロイセンターのベルトコンベア、クラスタ施設の窓の点灯（稼働の表現）、ネットワークセンターの光る線
- 建設は 3 段階（基礎 → 骨組み → 完成）で見せる。工事の日数（`docs/game-design.md` 15.2）を 3 つに等分する。工事の前の申請の間は、囲いと看板だけ（9.1）
- 動きを減らす設定では、動きを止める

## 7. 疑似 3D（2.5D）の描き方

- **等角投影（横 2 : 縦 1）。** 光は左上から。上面が最も明るく、左面が中間、右面が最も暗い
- 建物は必ず次を持つ: **奥行き・左右の側面・屋根（平屋根なら縁と設備、勾配屋根なら 2 面以上）・窓（面の傾きに沿う）・入口・外観の細部（庇・看板・設備・手すりなど 3 つ以上）・接地の影・道路との接続（敷地の舗装や車寄せ）・周辺環境（木・植え込み・街灯）**
- 四角形と三角形を重ねただけの家は禁止。CSS の図形で建物を作らない。絵文字を使わない
- 施設は自作 SVG（`src/city/assets/`）で描く。区画の建物は同じ描き方の規則で手続き的に生成してよい（見た目は自作 SVG と揃える）
- 名札は互いに重ならず、建物を隠さない（`docs/ui-design.md`）

## 8. 配置の規則

- 置ける所は緑の枠、置けない所は赤の枠と理由（道路に面していない・重なる・霧の中・資金が足りない・審議中の申請が多すぎる・財政が赤字（公共サービスと発電所）・発電所が道路に面していない）
- 申請の要る物は、置く前の枠の横に「申請になる」と、見込みの反対の理由（上位 2 つ）を出す（`docs/game-design.md` 16 章。置いた場所の模擬から計算する）
- R キーで 90 度回転、Esc で取り消し
- 取り壊しは確認してから。施設を壊しても学習の記録は消えない。申請中の物は、取り壊しではなく取り下げ（費用は戻る）
- 配置の判定は `src/city/` の純粋な関数で行い、テストする

## 9. 申請・公共サービス・電力

規則と数値は `docs/game-design.md` 15・24・25 章。ここでは、都市の上で何がどう見えるかを決める。

### 9.1 申請から完成までの見た目

| 段階 | 敷地の見た目 |
|---|---|
| 申請・用途地域の審査 | 敷地の縁に低い囲い（白と灰の板）。道路側に看板（施設の名前と「審議中」）。敷地の地面は今のまま |
| 反対の受付・公聴会 | 囲いの前に、反対する集団の小さな人の影（反対率に応じて 0〜6 人。顔は描かない）と、手に持つ札。反対率が 20% を超えると札の色が `state.warn`、50% を超えると `state.bad` |
| 議会の採決を待つ | 看板に議会の日付 |
| 異議申し立て | 囲いの入口に止まれの札。人の影は残る |
| 着工 → 完成 | 3 段（基礎 → 骨組み → 完成。6 章）。足場とクレーン。人の影は消える |
| 否決・取り下げ | 囲いを片付け、元の地面に戻る（1 日） |

- 看板と人の影は、名札と同じく互いに重ならない（`docs/ui-design.md` 8 章）。遠くでは人の影を間引き、看板だけを残す
- 申請中の敷地を押すと、申請の詳細の窓（`docs/ui-design.md` 10.2）が開く
- 用途地域の変更の申請は、塗った区画を破線の縁で示し、区画の中央に看板を 1 つ立てる

### 9.2 公共サービスの建物

学習者が置く。建設と維持は財政（`docs/game-design.md` 2・22 章）。7 章の描き方の規則（奥行き・側面・屋根・窓・入口・細部 3 つ以上・影・道路との接続・周辺環境）を全て守る。

| 建物 | 大きさ | 見た目の特徴 |
|---|---|---|
| 警察署 | 2×2 | 2 階建ての庁舎と車庫、屋上の無線の柱、前に並ぶ車 |
| 消防署 | 2×2 | 大きな車庫の扉と訓練の塔、赤い車 |
| 学校 | 3×2 | L 字の校舎と校庭（白線）、体育館、門と並木 |
| 診療所 | 1×2 | 白い 2 階建てと十字でない印（自作の記号）、車寄せ |

- 公共サービスに Lv は無い（1 つの見た目）。行き届く範囲は、表示切替の「公共サービスの行き届き」で色として見える（`docs/ui-design.md` 11 章）
- インシデント対応本部（IT 施設。消防署に似た建物）と消防署は、色（分野の差し色と赤）と車（出動車両と消防車）で見分けられるようにする

### 9.3 公共サービスと IT 施設の区別

役割が違うので両方を持つ。

| | 公共サービス（警察署・消防署・学校・診療所・公園の類） | IT 施設（4 章の 15 施設） |
|---|---|---|
| 役割 | **都市のための施設**。今いる住民の暮らし（治安・防災・教育・医療・緑地）を支える | **学習と技術のための施設**。学習の入口で、学習の成果が形になる場所 |
| 学習との関係 | 学習の入口ではない（情報パネルに「ここで学ぶ」は無い） | 対応する分野がある。情報パネルから学習へ進める（D-02） |
| 建てる財布 | 財政（税収） | 開発資金（学習で得た XP と同じ量） |
| レベル | 無い | 1〜5（スキル段階と資金。`docs/game-design.md` 5 章） |
| 都市への効き | 行き届き（距離で決まる）→ 満足と地価 | 雇用・技術力・地価・オフィスの需要。電力を多く使う物がある |
| 発展段階 | 数えない | Lv の合計が技術力 |

- 理由: 公共サービスを学習の入口にすると、IT と関係の無い施設（警察・学校）が学習の分野と結び付き、「IT 分野と施設は対応する」（`CLAUDE.md` 4 章）がぼやける。
  IT 施設に暮らしの役割を持たせると、学習をしないと住民の暮らしが立たず、学習が義務になる。分けることで、学習は都市を広げ・技術を育てる力、財政は今の暮らしを保つ力になる
- 公園の類は、今までどおり開発資金で置き、緑地の行き届きを持つ（公共サービスの一つとして数えるが、財布は開発資金。申請は要らない）

### 9.4 電力

- **発電所**（学習者が置く。財政。申請が要る）

| 発電所 | 大きさ | 見た目の特徴 |
|---|---|---|
| 火力の発電所 | 2×2 | 煙突 2 本（白い湯気。動きを減らす設定では止める）・タンク・変電の設備・囲いの塀 |
| 太陽光の発電所 | 3×3 | 傾いた板の列（面の傾きに沿った反射）・管理棟・変電の設備・周りの草地 |

- **送電**: 電気は道路に沿って届く。道路の縁に低い電柱を等間隔に描く（細い道と一般道。大通りは地中線で描かない）。発電所は道路に面していなければならない
- **陸揚げ所**: 島に初めからある海底ケーブルの陸揚げ所（小さな変電の建物と海へ伸びる線）。新しい都市では、初めに使える範囲（中央 24×24）の海岸のうち、中央に最も近いマスに置く（地形から決まる）。
  つながる道路網が無ければ、一番大きい道路網に地中線で自動でつなぐ（線は描かない）。今の保存データから移した都市にも、同じ決め方で置く。取り壊せない
- **停電**: 止まった地区の建物は、窓の灯りを消し、屋根の上に小さな「止まった」記号（自作 SVG。差し込みの抜けたプラグの形）を出す。表示切替の「電力」では、来ている所と止まった所を色で示す
- 電力の使用が多い施設（データセンター・クラスタ施設・クラウドセンター）は、情報パネルに使う量（MW）を出す

### 9.5 褒賞の建物

人口と支持率の節目で建てられるようになる（`docs/game-design.md` 25 章）。財政で建て、申請が要る。7 章の描き方の規則を守る。

| 建物 | 大きさ | 見た目の特徴 |
|---|---|---|
| 新しい市庁舎 | 2×2 | 時計のある塔と議場の丸屋根、前庭と旗の柱 |
| 市民記念館 | 2×2 | 列柱の入口と石の壁、前の広場 |
| 競技場 | 3×3 | 楕円の観客席と照明の塔、駐車場。試合の日は照明が灯る |
| 市民ホール | 2×2 | 大きなガラスの面と庇、前の階段 |
| 中央公園 | 4×4 | 池・遊歩道・芝・木立。噴水と東屋 |

### 9.6 素材

- 9.2・9.4・9.5 の建物と工業区画の建物は、施設と同じく自作 SVG（`src/city/assets/`）か、同じ描き方の規則の手続き的な生成で描く（`docs/visual-design.md` 5 章の規則のまま）
- `docs/visual-design.md` 6.1 の「施設 15 施設 × 5 レベル」は IT 施設の数。公共サービス・発電所・陸揚げ所・褒賞の建物は 1 つの見た目ずつで、置き場所は `src/city/assets/civic/<建物>.svg`（`docs/decisions.md` C-9）
