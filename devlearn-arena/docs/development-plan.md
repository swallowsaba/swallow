# 開発計画

完成の判定は `docs/acceptance-criteria.md`、テストの方法は `docs/testing-strategy.md`。
この文書は**Phase の順番と、各 Phase の範囲と完成条件**を決める。
Phase 0〜15 の後に、都市を作る仕組みを Permit Pending の形にする Phase G1〜G12 を進める（`docs/decisions.md` D-20。この文書の最後）。

## 進め方（全 Phase 共通）

```text
仕様確認 → 小さく実装 → 起動 → テスト → 画面確認 → 修正 → 次の Phase
```

- 1 つの Phase の中でも、意味のある単位でコミットする
- 各 Phase の最後に、完成条件・テスト・視覚確認の結果を `docs/progress/phase-<番号>.md` に記録する
- 「次への条件」を全て満たすまで次の Phase に進まない
- 「視覚確認」は `docs/visual-design.md` 8 章の項目（V1〜V11）のうち、その Phase に関係するもの

## Phase 0 仕様・設計と片付け

- **目的**: 仕様書を正とする状態にし、既存のコードの扱いを決める
- **実装対象**: この仕様書以外の指示書・設計書と旧 `docs/` を `docs/archive/` へ移す。
  既存のコードを調べ、この仕様書の要件を満たすか判定し、再利用する物と置き換える物を理由付きで `docs/archive/inventory.md` に一覧で書く（`docs/decisions.md` D-05）。
  three.js など不要になる依存を一覧に書く（削除は置き換え後）。ESLint に層の境界の規則を入れる
- **実装しないもの**: 新しい画面・新しい機能
- **成果物**: `docs/archive/` への旧文書の移動、`docs/archive/inventory.md`（既存コードの判定と理由）、層の境界の ESLint 規則、`docs/progress/phase-0.md`
- **完成条件**: 一覧ができている。既存のテストが全て通る。`docs/` が新しい仕様書だけになっている
- **テスト**: 既存のテストと型検査と lint が通る
- **視覚確認**: なし
- **次への条件**: 完成条件・テスト・視覚確認を満たし、記録した

## Phase 1 都市画面のプロトタイプ

- **目的**: 「都市が主役の PC ゲーム」の見た目と操作の土台を作る
- **実装対象**: Canvas 2D の等角投影の描画。浮いた島の地形・曲線の海岸線と川・カメラ（移動・拡大縮小・90 度回転）。
  手で置いた見本の街（道路・区画の建物・施設 3 種 Lv1）を描く。上の帯（中身は空でよい）。フォントと tokens の導入。
  画面を撮影できる状態（`docs/testing-strategy.md` 6 章）
- **実装しないもの**: 配置の操作・学習・保存
- **成果物**: `src/city/`（投影・地形・カメラ）と `src/city/render/`、見本の街、上の帯、`src/ui/tokens.ts` とフォント、撮影の仕組み（`npm run shoot`）
- **完成条件**: 1920×1080 で 60fps 前後（最低 30fps）。見本の街が `docs/visual-design.md` の V1 V3 V4 を満たす
- **テスト**: 投影の座標変換・描画順（奥から手前）の単体テスト。tokens 以外の色と文字の大きさが無いことの検査
- **視覚確認**: V1 V2 V3 V4 V6 V9 V11
- **次への条件**: 完成条件・テスト・視覚確認を満たし、記録した。見た目の水準をここで固め、以後は落とさない

# 仕組みを Permit Pending の形にする Phase（G1〜G12）

`docs/decisions.md` D-20 の仕組み（`docs/game-design.md` 13〜27 章）を作る。Phase 0〜15 の後に、G1 から順に進める。進め方は上の「進め方（全 Phase 共通）」と同じ。
各 Phase の終わりに、完成条件・テスト・視覚確認の結果を `docs/progress/phase-g<番号>.md` に記録する。完成条件の項目は `docs/acceptance-criteria.md` 7 章（S1〜）。

順番の理由:

- **G1 を最初に置く**: 反対率も支持率も、模擬から計算する（`docs/game-design.md` 0・16 章）。模擬が無いまま許認可を作ると、数字が乱数になり、後から入れ替えられない
- **G7 を早めに置く**: 学習との接続がこのゲームの芯（指示書 61 章）。後回しにすると、遊べる物はできても、学習ゲームでなくなる危険がある。G5（公聴会）と G6（議会）で「説明する」の器ができた直後に、学習とつなぐ
- **G12 が要る**: 施設を置いたらすぐ建つ前提の台本が壊れる。台本と通しの確認を流し直す

共通の決まり:

- **学習にロックを掛けない**（`docs/game-design.md` 20 章）。どの Phase でも、市政のどの状態からもレッスンを始められることを E2E で確かめ続ける
- **反対率・支持率を乱数で決めない。** `src/sim` に `Math.random`・`Date.now` が無いことを、層の境界の検査（ESLint と念のためのテスト）で確かめる
- 今のテストと E2E のうち「置いたらすぐ建つ」を前提にした物は、その前提が変わる Phase（G3）で、時間を進めて完成させる形に直す（テストを消さない）。`tools/scenarios/` の台本は G12 で直す
- 見た目は変えない（D-01・`docs/visual-design.md`）。新しい画面は今の HUD の窓と字と色で作る
- 1280×720 で常時の UI が 20% 以内（V9）を、上の帯に物を足す Phase ごとに測る（`docs/ui-design.md` 3 章）

## G1 都市の模擬の土台

- **目的**: 反対率も支持率も、ここから計算できる土台を作る
- **実装対象**: `src/sim/`（`docs/game-design.md` 13 章）: 住民（区画の建物ごとの 12 層の世帯）・事業者（業種・雇う人・成長と撤退）・地価と騒音（足し算と原因）・家賃と手頃さと引っ越し・雇用と通勤（8×8 の地区）・税収（計算だけ）・満足と支持率と内訳（13.8）・信頼の器。
  時間（止める・1 倍・2 倍・3 倍、1 日 2 秒、都市画面以外では止まる。13.1）。工業区画（区画の道具・建物の手続き的な生成・騒音）。

## G11 褒賞・始め方の選択

- **目的**: 節目で建てられる物が増え、始める時に手ごわさを選べるようにする
- **実装対象**: 褒賞 5 つ（`docs/game-design.md` 25 章）の節目の判定・建物の SVG・効き・褒賞の一覧（`docs/ui-design.md` 10.11）。
  始め方の選択（27 章。規模の選択は入れず、反対の組織化の度合いを選ぶ）と、その窓（10.12）。初回・設定の「最初からやり直す」・落選の後の「新しい都市で始める」の 3 つの入口。初回の操作説明に市政を足す
- **実装しないもの**: 新しい機能
- **成果物**: 褒賞の模型と建物と一覧、始め方の選択と窓、初回の操作説明の更新
- **完成条件**: 人口 1,000 で新しい市庁舎が建てられるようになり、建てると政治資本の上限が上がる。届いた後に人口が下がっても建てられる。手ごわい町では、同じ申請の反対率がふつうの 1.25 倍になる。起動直後の主画面が都市画面のまま（初回も、始め方の窓の後ろに都市が見える）
- **テスト**: 節目の判定（下がっても残る）。褒賞の効き。始め方ごとの係数・境・初めの政治資本。学習にロックが無い（褒賞はレッスンに関係しない）
- **視覚確認**: V1 V3 V4（褒賞の建物）V9。始め方の窓を開いた初回の画面で都市が見える
- **次への条件**: 完成条件・テスト・視覚確認を満たし、記録した

## G12 通しの確認

- **目的**: 施設を置いたらすぐ建つ前提の台本を直し、新しい仕組みの上で、学習と都市の両方を通しで確かめ直す
- **実装対象**: `tools/scenarios/loop.mjs`（ゲームループ G1〜G6）と `tools/scenarios/verify-lesson.mjs`・`verify-free.mjs`・`verify-wrong.mjs` の、都市の画面から施設を置いてレッスンへ入る道を、申請 → 審議 → 完成を待つ（時間を 3 倍にして進める）か、申請中の施設の情報パネルから学ぶ形に直す。
  `docs/progress/verify-all.md`・`verify-free.md` の確認を流し直す（レッスンの中身（解説・理解・クイズ・実戦）の確認は、そのまま生きる。都市から入る道だけを流し直す）。
  市政のゲームループの E2E（`docs/acceptance-criteria.md` 7 章）。全画面の撮影（新しい窓を含む）。性能の計測（3 倍の速さ・最も重い都市・ヒートマップを重ねた時）
- **実装しないもの**: 新しい機能
- **成果物**: 直した台本、流し直した確認の記録、市政の E2E、全画面の撮影と視覚確認の記録、性能の計測結果（`docs/progress/phase-g12.md`）
- **完成条件**: `docs/acceptance-criteria.md` の全項目（1〜7 章）が合格。直した台本で、ミッション 6 本と全レッスンの都市から入る道が通る
- **テスト**: `docs/testing-strategy.md` の全て（10 章の模擬と市政を含む）
- **視覚確認**: 全画面で V1〜V11（1920×1080 と 1280×720）
- **次への条件**: 完成条件・テスト・視覚確認を満たし、記録した。公開 URL への E2E と撮影も流し直す（Phase 14 の手順）
