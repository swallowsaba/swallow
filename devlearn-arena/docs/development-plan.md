# 開発計画

完成の判定は `docs/acceptance-criteria.md`、テストの方法は `docs/testing-strategy.md`。
この文書は**Phase の順番と、各 Phase の範囲と完成条件**を決める。

## 進め方（全 Phase 共通）

```text
仕様確認 → 小さく実装 → 起動 → テスト → 画面確認 → 修正 → 次の Phase
```

- 1 つの Phase の中でも、意味のある単位でコミットする
- 各 Phase の最後に、完成条件・テスト・視覚確認の結果を `docs/progress/phase-<番号>.md` に記録する
- 「次への条件」を全て満たすまで次の Phase に進まない
- 「視覚確認」は `docs/visual-design.md` 8 章の項目（V1〜V11）のうち、その Phase に関係するもの

---

## Phase 0 仕様・設計と片付け

- **目的**: 仕様書を正とする状態にし、既存のコードの扱いを決める
- **実装対象**: この仕様書以外の指示書・設計書と旧 `docs/` を `docs/archive/` へ移す。
  既存のコードを調べ、この仕様書の要件を満たすか判定し、再利用する物と置き換える物を理由付きで `docs/archive/inventory.md` に一覧で書く（`docs/decisions.md` D-05）。
  three.js など不要になる依存を一覧に書く（削除は置き換え後）。ESLint に層の境界の規則を入れる
- **実装しないもの**: 新しい画面・新しい機能
- **成果物**: `docs/archive/` への旧文書の移動、`docs/archive/inventory.md`（既存コードの判定と理由）、層の境界の ESLint 規則、`docs/progress/phase-0.md`
- **完成条件**: 一覧ができている。既存のテストが全て通る。`docs/` が新しい仕様書だけになっている
- **テスト**: 既存のテストと型検査と lint が通る
- **視覚確認**: なし
- **次への条件**: 完成条件・テスト・視覚確認を満たし、記録した

## Phase 1 都市画面のプロトタイプ

- **目的**: 「都市が主役の PC ゲーム」の見た目と操作の土台を作る
- **実装対象**: Canvas 2D の等角投影の描画。浮いた島の地形・曲線の海岸線と川・カメラ（移動・拡大縮小・90 度回転）。
  手で置いた見本の街（道路・区画の建物・施設 3 種 Lv1）を描く。上の帯（中身は空でよい）。フォントと tokens の導入。
  画面を撮影できる状態（`docs/testing-strategy.md` 6 章）
- **実装しないもの**: 配置の操作・学習・保存
- **成果物**: `src/city/`（投影・地形・カメラ）と `src/city/render/`、見本の街、上の帯、`src/ui/tokens.ts` とフォント、撮影の仕組み（`npm run shoot`）
- **完成条件**: 1920×1080 で 60fps 前後（最低 30fps）。見本の街が `docs/visual-design.md` の V1 V3 V4 を満たす
- **テスト**: 投影の座標変換・描画順（奥から手前）の単体テスト。tokens 以外の色と文字の大きさが無いことの検査
- **視覚確認**: V1 V2 V3 V4 V6 V9 V11
- **次への条件**: 完成条件・テスト・視覚確認を満たし、記録した。見た目の水準をここで固め、以後は落とさない

## Phase 2 都市・道路・建物

- **目的**: 学習者が都市を形づくれるようにする
- **実装対象**: 道路の敷設（直線と曲線・交差点・橋）、区画の指定、区画の建物の自動生成と成長、施設と公園の配置（判定と理由の表示、回転、取り消し、取り壊し）、
  全施設の SVG（Lv1 のみでよい）、車と人の動き、霧
- **実装しないもの**: 学習との接続・資金の増減（この Phase では資金は固定値）
- **成果物**: 道路・区画・施設・公園の配置と判定、区画の建物の生成と成長、全施設の Lv1 の SVG、車と人、霧
- **完成条件**: 村から町程度の都市を、学習者が自分で作れる
- **テスト**: 配置の判定・道路のつながり・区画の成長の計算（同じ入力から同じ結果）
- **視覚確認**: V1 V3 V4 V9 V10 V11。建設中の 3 段階と、車が動いていることを 2 枚の撮影の差で確かめる
- **次への条件**: 完成条件・テスト・視覚確認を満たし、記録した

- **視覚確認**: V1 V7 V9 V10
- **次への条件**: 完成条件・テスト・視覚確認を満たし、記録した

## Phase 5 学習コンテンツの構造

- **目的**: コンテンツをデータとして足せる仕組みと、自由に学べる入口を作る
- **実装対象**: `content/` の形（`docs/content-spec.md`）と zod の検証、読み込み、用語集。学習ライブラリ（推奨学習順の並び・検索・絞り込み）と入口の札（推奨前提・関連・次）。
  知識グラフの表示。`docs/curriculum.md` の全レッスンの「目録」（ID・題名・難易度・前提・関連）。最初のレッスン 2 本（`docs/lessons/found.md` の found.b.04 と `docs/lessons/linux.md` の linux.i.01 の設計を書き起こす）
- **実装しないもの**: レッスンの各段の画面
- **成果物**: `content/` の形と検証、用語集、学習ライブラリ、入口の札、知識グラフ、全レッスンの目録、最初のレッスン 2 本
- **完成条件**: 全レッスンが目録にあり、どれでも「始める」を押せる。前提の未修了は案内だけで禁止しない
- **テスト**: 検証（`docs/content-spec.md` 6 章）。推奨前提の循環が無い。どのレッスンにもロックが無い
- **視覚確認**: V2 V5 V7 V8
- **次への条件**: 完成条件・テスト・視覚確認を満たし、記録した

## Phase 7 実戦とエラー学習

- **目的**: 安全な模擬環境で操作させ、失敗から学ばせる
- **実装対象**: 仮想端末（既存エンジン）を実戦に接続、状態による判定、ヒント 3 段、エラー学習（エラー → 内容 → 原因候補 → ヒント → 再挑戦）、結果とまとめ。
  新しい模擬環境の最小版: container と docker・http・tls・db（sql.js）
- **実装しないもの**: 監視と CI/CD の模擬（Phase 10 で分野と一緒に作る）
- **成果物**: 実戦の接続、状態による判定、ヒント、エラー学習、結果とまとめ、container・docker・http・tls・db の模擬環境
- **完成条件**: 見本の 2 本を最後まで通せる。わざと誤ると原因候補とヒントが出て、再挑戦で成功できる
- **テスト**: 各模擬環境の単体テスト。最後のヒントで必ず通ること。エラーの案内が出ること
- **視覚確認**: V2 V8
- **次への条件**: 完成条件・テスト・視覚確認を満たし、記録した

## Phase 8 学習と都市成長の接続

- **目的**: 完成条件のゲームループを初めて通す
- **実装対象**: 学習の結果 → XP・スキル・資金 → 都市（施設のアップグレード・区画の成長・発展段階）。都市へ戻った時に変化の場所へカメラが寄る。次に学ぶとよい内容を通知とおすすめの欄に出す
- **実装しないもの**: ミッション
- **成果物**: 学習から都市への反映、変化の場所へのカメラ、おすすめの欄、ゲームループの E2E
- **完成条件**: `docs/acceptance-criteria.md` の「ゲームループ」を、見本の 2 本で通せる
- **テスト**: 統合テスト（学習記録 → 都市の状態）。E2E で 1 周
- **視覚確認**: V1 V9。学習前と後の都市の撮影を並べて、変化が見て分かること
- **次への条件**: 完成条件・テスト・視覚確認を満たし、記録した

## Phase 10 学習コンテンツの拡充

- **目的**: 初回公開の範囲（`docs/decisions.md` Q-04）のコンテンツを揃える
- **実装対象**: 推奨学習順に、分野ごとにレッスンを作る。**分野ごとに完成条件・テスト・視覚確認を記録する**。
  順番: found → linux → net → web（＋ sec 初級の TLS）→ git → trouble 初級 → sec 初級の残り → db → cicd（模擬を作る）→ ctr → docker → k8s → mon（模擬を作る）→ cloud → devops → lab。
  模擬環境（模）の 5 つの型（`src/engines/sim`）と画面は、最初の分野（found）で作り、分野ごとに足りない物を足す。cicd・mon の模擬も、この型で作る（`docs/decisions.md` D-16）
- **実装しないもの**: 上級の全て（初回範囲外のもの）。分野ごとの専用の模擬環境（D-16。将来拡張）
- **成果物**: 初回公開の範囲の全レッスン（分野ごと）、模擬環境（模）の 5 つの型（cicd・mon の模擬を含む）
- **完成条件**: 範囲内の全レッスンが検証を通り、最後のヒントで通る
- **テスト**: コンテンツの検証（全件）
- **視覚確認**: 分野ごとに 1 本、全段を撮影
- **次への条件**: 全分野で完成条件・テスト・視覚確認を満たし、記録した

## Phase 15 必要に応じて Cloudflare Workers

- **目的**: GitHub Pages だけでは実現できない機能が**決まった場合だけ**作る
- **実装対象**: `docs/decisions.md` で決まった機能のみ（候補: 端末間の同期）。使う前に `docs/free-services.md` を公式情報で更新
- **実装しないもの**: 決まっていない機能。Workers を使うこと自体を目的にした機能
- **成果物**: 決まった機能の Workers と、更新した `docs/free-services.md`（決まっていなければ「不要」の記録）
- **完成条件**: 無料枠の範囲で動き、秘密が GitHub Pages 側に無い。Workers が止まってもゲームと学習が続けられる
- **テスト**: API・CORS・Secrets・エラー時の動作
- **視覚確認**: 該当画面
- **次への条件**: 完成条件・テスト・視覚確認を満たし、記録した。決まっていない場合は、この Phase を「不要」と記録して完了
