## テスト

- `npm run typecheck`・`npm run lint`・`npm run test`（190 ファイル・2,126 件）・`npm run content:check`・`npm run secrets` が通る

- 申請中の敷地には、ほかの物（施設・区画・道路）を置けない。否決から 28 日は同じ場所に同じ物を出せない
- 保存: 審議中・工事中・取り下げ・議会を待つ申請と、工事の終わる日を持つ施設が、保存・読み込みで元に戻る（`saveData.test.ts`）

## 性能（`npm run bench:sim`、手元の PC）

この Phase の初めに測ると、1 週の最大が 60.3〜69.5ms と目安（60ms）を超えていた（道路が変わった週と、ごみ集めの重なった週）。この Phase の中で直した。

- 道路の網: 地区ごとの探索を、地図の全てのマス（9,216）の配列ではなく、道路のマスだけの配列で行う（地区ごとに作っていた約 5MB の配列が無くなる）。結果は同じ（探す順も同じ）
- 原因の内訳: 建物ごとに鍵の文字列を作らない（要因 → 種類 → ID の順に引く）。仕事・通勤・税・信頼の原因は足してから 1 度だけ入れる
- 要因の点: 重みを掛ける時に配列を作り直さない

```text
道路の網（地区ごとの探索。道路が変わった週だけ）: 4.6ms（前 12.8〜14.1ms）
1 日（週の終わりでない日）: 平均 0.409〜0.447ms（目安 0.5ms 以下）
1 週（毎週の計算）: 平均 35.1〜36.2ms・最大 51.3〜57.2ms・道路が変わった週 50.5〜51.7ms（目安 30〜60ms）
結果: 目安以内（3 回とも）
```
