# Phase 7 実戦とエラー学習

記録した日: 2026-10-03

## 実装したこと

- 新しい模擬環境の最小版（純粋な TS。React に依存しない）
  - `src/engines/kernel/services.ts` と `systemctl`・`journalctl`: 今動いているか（active / inactive / failed）と起動時の登録（enabled）の 2 つの軸。壊れたサービスは failed になり、理由がログに残る
  - `src/engines/container`（イメージ・置き場・コンテナ・ポートの公開・ボリューム・環境変数）と、その上の `src/engines/docker`（docker の CLI）
  - `src/engines/http`（名前・ポート・道ごとの答え。手元のサービスと公開したコンテナのポートが localhost に応える）と `curl`
  - `src/engines/tls`（葉 → 中間 → 信頼するルートの検証。期限切れ・名前違い・中間の送り忘れ・知らない発行者・自己署名）
  - `src/engines/db`（sql.js の SQLite。実戦ごとに新しい DB。判定は問い合わせの結果。`docs/architecture.md` 2 章に sql.js を足してから入れた）
- `src/engines/environments.ts`: 実戦の模擬環境の土台（練習用の機械・サーバ・コンテナの動く機械・Web を確かめる機械・ブラウザ内の DB）と、`setup` の形（zod）。土台に setup を重ねて端末の初期状態を作る
- `src/learning/practice.ts`: 実戦の進み
  - 判定は出力ではなく模擬環境の状態（`fs`・`cwd`・`service`・`http`・`tls`・`answer`）。1 つの操作で続く手順をまとめて満たせる
  - ヒントは手順ごとに 3 段（方向 → 具体 → そのまま打てる答え）
  - エラーの文が出たら、手順で想定したエラー → 全てのエラーの解説 → 一般的な案内、の順に解説を探す。終了の値だけではエラーにしない（`systemctl status` は止まっていれば 3）
  - 前のエラーの後にヒントを開かずに満たすと「エラーから自力で回復」。危ない手は記録して成功はさせる。結果の文（success・partial・retry）の選び方
  - 今打てるコマンドの候補（手順の目的と、答えでないヒントに出たコマンド）
- 検証（`docs/content-spec.md` 6 章）に、模擬環境があること・setup の形・**全実戦の最後のヒントを初期状態から順に打つと達成条件を満たす**ことを足した
- レッスン画面の後半（`src/screens/lesson/`）
  - 実戦: 左に目的・手順（打つ前に何を確かめるか、満たすと「何が起きたか」）・ヒント 3 段、右に仮想端末（施設の景色の上の窓）。
    エラーが出ると端末の下に「エラーが出た。調べてみよう」の小窓（打った行とエラーの文 → 何と言われたか → 考えられる理由 → 次に確かめること → もう一度打ってみよう）。
    初めに戻す・ここで終えて結果を見る（未達でも責めない）。打つたびに途中の状態（シェルの状態と実戦の進み）を保存し、中断して開き直すと打った所から続く。実戦では右（端末）を広くする
  - 結果: 自分の手で通せた / ヒントを使って通せた / まだ途中、と結果の文。できたこと・まだの手順・よかった手・次はここを・打ったコマンド。もう一度挑戦できる
  - まとめ: 要点・次に学ぶとよい（入口の札へ）・関連用語（押すと小窓）
  - XP / スキル: できるようになったこと（到達目標）・分野のスキルの段階の変化と「何をしたからこの値か」・称号・都市への影響（開発資金）・得た XP の内訳。都市へ戻る
- 仮想端末: 既存の xterm の端末を `src/screens/lesson/terminal/` へ移して再利用（`docs/archive/inventory.md` の判定を「再利用」に。`docs/architecture.md` 2 章に @xterm を足した）。
  色と字は tokens（JetBrains Mono 14px）。プロンプトは利用者と機械の名前から（`learner@arena:~$`・`root@server:/root#`）。使わない部品（図から打ち込む部品・時間をさかのぼる部品）を削除
- 撮影の台本 `SHOOT_SCRIPT=tools/scenarios/practice.mjs npm run shoot -- p7-end`

## テスト

- `npm run typecheck` `npm run lint` `npm run test`: 全て通過（128 ファイル・5,033 件）。`npm run build` も通る
- 各模擬環境の単体テスト: サービス（`systemctl.test.ts`）・コンテナ（`container.test.ts`）・docker（`cli.test.ts`）・HTTP（`http.test.ts`）・TLS（`tls.test.ts`）・DB（`db.test.ts`）・模擬環境の土台（`environments.test.ts`）
- 最後のヒントで必ず通ること: 見本の 2 本で `replayAnswers` が問題なし。通らない実戦（最後のヒントを変えたもの）は検証で見つかる（`practice.test.ts`・`validate.test.ts`）
- エラーの案内が出ること: 想定エラー（enoent・unit-not-found・service-failed）と一般的な案内。終了の値 3 の `systemctl status` はエラーにしない。画面では小窓の中身（内容・原因候補 2 つ以上・次に確かめること）まで確かめた
- 状態による判定: `pwd` や `echo /srv/app` では進まず、相対パスで着いても通る。`start` だけでは通らず `enable` を足すと通る
- XP: 実戦の成功（初級 20・中級のヒントあり 35 ÷ 2 = 17.5 → 18）・自力の回復 +10・修了 30。得た XP と同じ量が都市の資金に入る
- 途中保存と再開: 実戦の途中で中断して開き直すと、打った所（`/srv`）から続く。未達のまま終えると retry、もう一度挑戦すると模擬環境は初めから
