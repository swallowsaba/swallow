【0】何をするか

初回公開の範囲（docs/decisions.md の Q-04）は 211 本中 131 本。
この 131 本は、通しの確認が終わっている
（docs/progress/verify-all.md・docs/progress/verify-free.md）。

残る 80 本（中級 34・上級 46）を、同じ品質で書き起こし、同じ確認を
通す。設計は docs/lessons/ に 211 本すべて既にある。無いのは
content/lessons/ の中身（実際に遊べる形）だけ。

【3】書き起こしの決まり
---------------------------------------------------------------------------

既にある 131 本と同じにする。新しい決まりは作らない。

- 形は docs/content-spec.md。検証は npm run content:check
- 中身は docs/lessons/<分野>.md の設計のとおり。
  設計と違う中身にしたい場合は、先に設計を直す（docs/content-spec.md 5.1）
- 実戦は REWORK-PRACTICE.txt の原則 1〜5
  - 本物の道具を使う（git・kubectl・docker・curl・SQL・設定の編集）
  - 画面の操作（模）は、打つコマンドが存在しない概念だけ
  - 文を打つ入力欄を作らない。ドラッグと、何をするかが文字で分かる釦
  - 結果を動きで見せる
  - 左の目的に出る名前が、右の画面にそのまま出る
- 判定は、コマンドの実行と模擬環境の状態で行う（docs/content-spec.md 2.4）。
  手で打つ答えの欄は、コマンドでは出せない値だけ
- 見せるための失敗は designedErrors を付ける（docs/content-spec.md 2.4）
- 「今打てるコマンドの候補」に、その実戦で使うコマンドを全て出す
  （docs/learning-design.md 8 章）
- クイズは 3 問以上・3 種類以上。理解は 2 つ以上（docs/lessons/README.md）

上級と lab で足りない物があれば、模擬環境に足す。本物にある振る舞いに
合わせる（src/engines/）。足した物はテストを書いてから入れる。

【4】1 分野ずつ進める
---------------------------------------------------------------------------

順は、中級の残り（found・sec・cicd・db・mon・cloud・devops・trouble）を
先に、その後に上級（推奨学習順の並び: linux・net・web・sec・git・cicd・
ctr・docker・k8s・db・cloud・mon・devops・trouble・found・lab）。

1 つの分野を書き終えるごとに、次を全て行う。

1. npm run typecheck / npm run lint / npm run test / npm run content:check
2. その分野の新しいレッスンに、確認の台本を流す
   - node tools/scenarios/verify-all.mjs <分野>（最後のヒントの通り）
   - 別解を tools/scenarios/variants/<ID>.json に 2 通り以上書き、
     node tools/scenarios/verify-free.mjs <分野>（ヒントを開かない）
   - node tools/scenarios/verify-wrong.mjs <分野>（わざと間違える）
   - ドラッグの実戦があれば node tools/scenarios/verify-drag.mjs
3. 不合格は原因ごとに直す。先に失敗するテストを書く（CLAUDE.md 13 章）
4. docs/progress/expand-scope.md に、分野ごとの表を書く
   （本数・不合格・原因・直したこと）
5. コミットして push する

1 本ごとに全体を流し直さない。分野の単位で回す。

【6】やってはいけないこと
---------------------------------------------------------------------------

  その時は理由を記録に書く）

【7】進め方
---------------------------------------------------------------------------

  - 【1】の決着を先に書いてコミットする
  - docs/progress/expand-scope.md があれば読み、記録の続きの分野から進める

    出力して終われ
