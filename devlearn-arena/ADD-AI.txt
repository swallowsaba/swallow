===========================================================================
AI エンジニアの分野を足す（G 検定の範囲・統計）
===========================================================================

【0】何をするか

利用者の指示により、学習分野に次の 2 つを足す。

  - AI・機械学習（G 検定の出題範囲に沿う）
  - 統計（統計検定の出題範囲に沿う）

今の 16 分野・211 本に並ぶ形で、設計から書き起こしまで行い、
既存と同じ確認を通す。

---------------------------------------------------------------------------
【1】最初に、決着を書く
---------------------------------------------------------------------------

最重要指示（__最重要指示.txt）19 章の学習対象に AI・機械学習と統計は
無い。CLAUDE.md 14 章は「根拠は仕様書だけ。仕様書に無い機能・画面・
要素を、ほかの経緯から持ち込まない」と定めるので、決着を書かない限り
この追加は規則違反になる。

docs/decisions.md の決着に D-21 として書く。

- 問題: 指示書 19 章の学習対象に AI・機械学習と統計が無い。
  利用者が、AI エンジニアになるための分野として、G 検定の範囲の解説と
  問題、および統計検定の範囲を足すよう指示した
- 決着（利用者の指示）: 学習分野に ai（AI・機械学習）と stat（統計）を
  足す。指示書 19 章の一覧は最低限の指定（「最低限、以下を含める」）
  であり、足すことを禁じていない
- 要決定事項 Q-04（初回公開の範囲）を、この 2 分野を含む形に広げる

### 守る規則（これを破ると作り直しになる）

- 公式の過去問を写さない。G 検定・統計検定の実際の問題、公式教材の
  文・図・表を、そのまま写したり言い換えたりして使わない。
  出題範囲（シラバス）に沿った自作の問題だけを書く
- 公式との関係を騙らない。「G 検定の出題範囲に沿う」のような範囲の
  説明は書いてよい。公式の認定・提携・合格保証を思わせる表現、
  ロゴ・意匠は使わない
- 既存の規則は全て生きる。どこからでも学べる・ロックを作らない・
  7 段の学習フロー・実戦は本物の道具・無料・ライセンス不明の素材を
  使わない

【2】範囲を決める
---------------------------------------------------------------------------

### 2.1 ai（AI・機械学習）

G 検定の出題範囲に沿って、次をすべて含む。公式のシラバスの区分を
そのまま章立てにせず、この教材としての並びに組み直してよい。

  - 人工知能とは・歴史（探索・推論、知識表現、機械学習の広がり）
  - 機械学習の基礎（教師あり・教師なし・強化学習）
  - 主な手法（回帰、分類、決定木、SVM、クラスタリング、次元削減、
    アンサンブル）
  - 評価（訓練と検証と試験、交差検証、過学習と未学習、
    正解率・適合率・再現率・F 値・ROC・AUC、混同行列）
  - ニューラルネットワークの基礎（順伝播、誤差逆伝播、活性化関数、
    損失関数、勾配降下法、学習率）
  - 深層学習（CNN、RNN、LSTM、注意機構、Transformer）
  - 深層学習の実務（正則化、ドロップアウト、バッチ正規化、転移学習、
    データ拡張、ハイパーパラメータ）
  - 生成モデル（GAN、拡散モデル、大規模言語モデルの基礎）
  - 分野ごとの応用（画像、自然言語、音声、推薦、異常検知）
  - AI の社会実装（PoC から運用、MLOps の基礎、データの偏り、
    説明可能性、法と倫理、個人情報、著作権、AI の規制の動き）

### 2.2 stat（統計）

統計検定の出題範囲に沿って、次をすべて含む。
3 級〜2 級の範囲を中心に、準 1 級の内容の一部を上級に置く。

  - 記述統計（代表値、散らばり、四分位、箱ひげ図、ヒストグラム、
    相関、分割表）
  - データの取り方（標本と母集団、無作為抽出、実験と観察、交絡、
    バイアス）
  - 確率（条件付き確率、ベイズの定理、独立）
  - 確率分布（二項、ポアソン、正規、t、カイ二乗、F）
  - 標本分布と推定（大数の法則、中心極限定理、点推定、区間推定）
  - 仮説検定（帰無仮説と対立仮説、有意水準、p 値、第 1 種・第 2 種の
    過誤、検出力、t 検定、カイ二乗検定、分散分析）
  - 回帰（単回帰、重回帰、最小二乗法、決定係数、残差、多重共線性）
  - ノンパラメトリックの基礎
  - 時系列の基礎（トレンド、季節、自己相関）
  - 上級（準 1 級の一部）: ベイズ統計の基礎、一般化線形モデル、
    主成分分析、クラスター分析、実験計画

### 2.3 本数と難易度

docs/curriculum.md の既存の分野と同じ密度にする。
目安は各分野 40〜50 本、初級・中級・上級を揃える。
正確な本数は設計で決め、理由を書く。

【3】実戦をどうするか（一番大事な所）
---------------------------------------------------------------------------

CLAUDE.md 15.1 と REWORK-PRACTICE.txt の原則 1〜5 は、この 2 分野にも
そのまま当てる。

  1. 本物の道具を使う
  2. 画面の操作（模）は、打つコマンドが存在しない概念だけ
  3. 文を打つ入力欄を作らない（ドラッグと、何をするかが文字で分かる釦）
  4. 結果を動きで見せる
  5. 左の目的に出る名前が、右の画面にそのまま出る

統計と機械学習の「本物の道具」をどうするかを、設計の段で決めて理由を
書く。次の 3 つを検討し、レッスンごとに選ぶ。

- 既にあるブラウザ内の SQL（sql.js）。集計・分布・相関・分割表・
  層別は、実際に SQL を書いて数える形にできる。分散を
  AVG(x*x) - AVG(x)*AVG(x) で書くような、式を自分で組む実戦にすると、
  意味の理解と手を動かすことが一致する
- 新しい模擬の道具を src/engines/ に足す。統計と機械学習の実務の
  道具は Python（numpy・pandas・scikit-learn）なので、既にある
  git・docker・kubectl と同じやり方で、その実戦に要る範囲だけの
  模擬を作る。足す場合は、本物と同じ出力・同じエラーにし、テストを
  書いてから入れる。大きな外部の部品（Pyodide など）は入れない
  （指示書 35・40 章。無料・必要最小限・GitHub Pages で動く）
- 画面の操作（模）。打つコマンドが無い概念だけ。例:
  - つなぐ: ニューラルネットの層、学習と検証と試験の流れ
  - 並べる: 誤差逆伝播の順、PoC から運用までの段、検定の手順
  - 置く: 混同行列の 4 つの枠に事例を入れる、分布と場面の対応、
    教師あり・教師なし・強化の仕分け
  - 読み取って答える: ROC 曲線、学習曲線、残差プロット、箱ひげ図、
    p 値の表

やってはいけない形: 計算の答えだけを手で打たせる実戦。
それは「問題を解く」であって「操作して結果を見る」ではない
（指示書 51 章）。数を出す実戦は、必ず道具で計算させる。

【4】都市とのつながり
---------------------------------------------------------------------------

指示書 28 章は、IT 分野と都市施設を対応させる。

- 2 分野を、どの施設に対応させるかを決める。
  既にある研究施設に両方を割り当てるか、新しい施設を足すかを選び、
  理由を書く。新しい施設を足す場合は、自作 SVG の絵が Lv1〜5 で
  要る（docs/visual-design.md・docs/city-design.md）。
  絵を増やさない選択（既存の研究施設に割り当てる）も妥当
- スキルの一覧（docs/game-design.md）に、この 2 分野を足す
- 市政との接続（決着 D-20）: 反対の理由と、公聴会の「説明する」の手に、
  この 2 分野で答えられる論点を足す（content/politics/）。例:
  「この AI の判定は偏っていないのか」「その効果は誤差の範囲ではないのか」
- 知識グラフ（推奨前提・関連・次に学ぶとよい）を、既存の分野と
  つなぐ。統計 → 機械学習、Linux/Python → 機械学習、
  データベース → 統計、クラウド → AI の社会実装 など

【5】進め方（段）
---------------------------------------------------------------------------

### 段 1: 決着と設計（コードを書かない）

1. docs/decisions.md に D-21 を書いてコミット
2. docs/curriculum.md に 2 分野の表を足す
   （ID / 難易度 / テーマ / レッスン / 到達目標 / 実戦の形 /
   推奨前提 / 関連 / 次に学ぶとよい）
3. docs/lessons/ai.md・docs/lessons/stat.md に、全レッスンの
   7 段の設計を書く（docs/lessons/README.md の形）
4. 【3】で決めた実戦の道具と、その理由を docs/learning-design.md に書く
5. 【4】の施設・スキル・市政・知識グラフの決定を、該当の仕様書に書く
6. docs/development-plan.md に、書き起こしの Phase を足す
7. npm run content:check が通ることを確かめてコミット

### 段 2: 書き起こし

テーマごとに content/lessons/ai/・content/lessons/stat/ へ書く。
既存の 131 本と同じ決まり（docs/content-spec.md・
REWORK-PRACTICE.txt・designedErrors・コマンドの候補）。

新しい模擬の道具を足す場合は、先にテストを書いてから入れる。

### 段 3: 確認

テーマを書き終えるごとに、

  - npm run typecheck / lint / test / content:check / secrets
  - node tools/scenarios/verify-all.mjs <ID の並び>
  - 別解を tools/scenarios/variants/<ID>.json に 2 通り以上書いて
    verify-free.mjs
  - verify-wrong.mjs
  - ドラッグの実戦があれば verify-drag.mjs
  - git push して公開 URL で確かめる
  - docs/progress/add-ai.md に表で記録してコミット

全部書き終えたら、2 分野の全レッスンに 4 つの台本を 1920x1080 と
1280x720 で流し、結果を docs/progress/add-ai.md にまとめる。
